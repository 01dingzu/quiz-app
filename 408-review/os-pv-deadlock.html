考点 1 · 信号量与 PV 操作基础

选择题必考 · 记录型信号量的值是判断一切的钥匙

信号量 S = 一个整型值 value + 一个等待队列。P 操作（wait）：value 减 1，若减完 value < 0 则进程阻塞入队；V 操作（signal）：value 加 1，若加完 value ≤ 0 则从队头唤醒一个进程。

value 的含义：正值 = 还可用的资源数；0 = 资源刚好用完、无人排队；负值 = 绝对值就是阻塞等待的进程数。这一条能秒杀一半的选择题。

初值怎么定：互斥信号量初值 = 1；同步信号量初值 = 可用资源个数（如缓冲区空位数）。

P/V 都是原语：执行过程不可中断，这是保证计数值不出错的根本。

易错：同步 P 在前、互斥 P 在后。顺序颠倒可能导致持有互斥锁的进程去等一个永远等不到的资源——死锁。

例题 1 · 值的推演
信号量 S 初值为 2，当前值为 -1。此时等待队列中有几个进程？若再执行一次 V 操作，S 的值变为多少，队列状态如何？
展开完整推演

第一步：当前值 -1 < 0，负值的绝对值 = 阻塞进程数，所以等待队列中有 1 个进程。

第二步：执行 V：value 加 1，-1 + 1 = 0。因为加完 ≤ 0，说明还有进程在等，于是唤醒队列中的一个进程，该进程进入就绪态。

第三步：此时 value = 0，队列变空。注意 V 之后 value = 0 不是"没资源"，而是"资源刚被唤醒者领走、无人排队"。

答：等待 1 个进程；V 后 S = 0，唤醒一个进程后队列空。

例题 2 · 顺序颠倒的死锁推演
生产者-消费者问题中，把生产者的 P(mutex) 写在 P(empty) 之前，且缓冲区已满。推演会发生什么。
展开完整推演

设 mutex=1、empty=0（满）、full=n。生产者进入：

P(mutex)   成功，mutex 变 0，生产者拿到锁
P(empty)   empty 变 -1，生产者阻塞，等待空位
消费者     想取产品，执行 P(full) 成功，
           接着 P(mutex) —— 但 mutex 是 0，
           被持锁的生产者占着，消费者阻塞

结论：生产者锁着门等空位，消费者有资格腾空位却进不了门——两个进程互相等待，死锁。所以"同步 P 在前，互斥 P 在后"不是风格问题，是正确性问题。

考点 2 · 生产者-消费者问题

大题第一模板 · 必须做到默写零错

标准模板（缓冲区 n 个，多生产者多消费者）：

semaphore mutex = 1;   // 互斥访问缓冲区
semaphore empty = n;   // 空位数（同步）
semaphore full  = 0;   // 产品数（同步）

生产者:                     消费者:
while(true){                while(true){
  生产一个产品;                P(full);
  P(empty);                   P(mutex);
  P(mutex);                   从缓冲区取产品;
  放入缓冲区;                 V(mutex);
  V(mutex);                   V(empty);
  V(full);                    消费产品;
}                           }

三条铁律：① 两个 P 不可交换（同步在前）；② 两个 V 可以交换（V 不会阻塞）；③ mutex、empty、full 各司其职，多对生产者消费者时 mutex 仍只需 1 个。

例题 · 初值设定与死锁时序
缓冲区容量为 3，两个生产者、一个消费者。写出三个信号量的初值；并说明若消费者写成 P(mutex); P(full);，在缓冲区为空时的死锁时序。
展开完整推演

初值：mutex = 1（临界区只容一个）；empty = 3（3 个空位）；full = 0（初始无产品）。与生产者消费者个数无关——它们保护的是缓冲区，不是进程。

死锁时序（初始 empty=3, full=0）：

t1  消费者 P(mutex) → mutex=0，拿到锁
t2  消费者 P(full)  → full=-1，阻塞等产品
t3  生产者 P(empty) → empty=2，成功
t4  生产者 P(mutex) → mutex=-1，阻塞等锁
    ⇒ 消费者等"产品"，生产者等"锁"，
      锁在等"产品"的人手里。死锁。

要点：给"为什么死锁"写答案时，按 t1~t4 这种编号时序写，阅卷最清晰。

考点 3 · 读者-写者问题

选择题考变体识别 · 大题考模板默写

读者优先模板（允许多读者并发，读者来了不用等写者以外的任何人）：

int count = 0;            // 正在读的读者数
semaphore mutex = 1;      // 保护 count 的互斥
semaphore w = 1;          // 读写互斥、写写互斥

读者:                       写者:
P(mutex);                   P(w);
if(count==0) P(w);          写;
count++;                    V(w);
V(mutex);
读;
P(mutex);
count--;
if(count==0) V(w);
V(mutex);

两行灵魂代码：只有第一个读者 P(w)（把写者挡在门外），只有最后一个读者 V(w)（放写者进来）。count 为什么要 mutex 保护？——两个读者同时发现 count==0，会各自 P(w) 一次，第二个读者自己把自己锁死在门外。

写者优先：再加一个排队信号量（如 queue）+ 写者计数，使"写者之后到达的读者"排在写者后面，防止读者流饿死写者。

例题 · 谁来 V(w)
读者 R1 正在读。R2、R3 相继到达，随后 R1 退出、R2 退出、R3 退出。问：哪几次操作执行了 P(w)？哪一次执行了 V(w)？逐次推演 count 的值。
展开完整推演 
      count 动作            count   w
R1到  P(mutex);count==0→P(w)  0→1   1→0 持有
R2到  count==1,不P(w)         1→2   仍0
R3到  count==2,不P(w)         2→3   仍0
R1退  count-- → 不是0,不V(w)  3→2   仍0
R2退  count-- → 不是0,不V(w)  2→1   仍0
R3退  count-- → 等于0→V(w)    1→0   0→1 释放

答：P(w) 只在 R1 进入时执行一次；V(w) 只在最后一个退出的 R3 处执行。中间的读者进出只动 count。

考点化：这类推演做成选择题，常把"最后一个退出的读者"换成"第一个读者"当干扰项——记住 V(w) 永远跟着 count 归零走。

考点 4 · 哲学家进餐与死锁预防

选择题考"打破了哪个条件" · 必须能对号入座

死锁四个必要条件：互斥、请求与保持（拿着手里的还要等新的）、不可剥夺、循环等待。破坏任何一个即可预防。

哲学家死锁成因：5 人同时拿起左筷子，每人都在等右筷子 → 循环等待。

三种经典解法与对应的"破坏对象"：

① 最多允许 4 人同时拿筷子 → 破坏循环等待
② 奇数号先拿左、偶数号先拿右 → 破坏循环等待
③ 一次性拿齐两根（要么全拿要么不拿）→ 破坏请求与保持

易混淆点：①② 方案下"先拿一根再等一根"的持有行为还在，所以不是破坏请求与保持；③ 才是。银行家算法属于"避免"，不是"预防"——预防是静态破坏条件，避免是动态判断安全性。

例题 · 奇偶方案为什么有效
哲学家 P0~P4 围坐，筷子编号 0~4，Pi 左手是 i 号、右手是 (i+1)%5 号。采用"奇数号先左后右、偶数号先右后左"。推演为什么不会死锁。
展开完整推演

看最关键的 P0（偶，先右即先拿 1 号）和 P1（奇，先左即先拿 1 号）：两人争同一根筷子，必然一人拿走、另一人阻塞——至少一根筷子始终有人用。

逐条检查：P0 拿 1 号成功 → P1 阻塞在 1 号；P2（偶，先拿 3 号）；P3（奇，先拿 3 号）与 P2 竞争；P4（偶，先拿 0 号）。

若 5 人同时行动：P0 持 1 等 0，P4 持 0 等 4，P3 或 P2 之一持 3 等 2/4……任何时刻总存在"持有一根、竞争同一根"的赢家，资源链不会闭合成环。环路被打断，死锁无法形成。

考点 5 · 死锁、安全状态与银行家算法

大题必考计算 · Need = Max - Allocation 是入口

三个必背关系：Need = Max − Allocation；安全序列存在 ⇔ 系统安全；安全状态一定无死锁，不安全状态不一定死锁（只是可能死锁）。

银行家算法（避免）：每次分配前试探，找一个进程使 Need ≤ Available，模拟其归还后 Available 增大，继续找——全部能找完则存在安全序列，分配；否则拒绝。

死锁处理三档策略：预防（静态破坏条件）< 避免（动态安全判断）< 检测+解除（鸵鸟之外的兜底，解除手段：剥夺资源、撤销进程）。

资源分配图有环 ≠ 死锁：每类资源只有 1 个时，环路 ⇔ 死锁；资源有多个时，环路可能化简（死锁定理：不可化简才是死锁）。

例题 · 银行家算法全流程推演
系统有两类资源 R1、R2，共 4 个 R1、4 个 R2。当前分配如下（每格为 R1, R2）： 
     Allocation   Max      Need
P0     1,1        2,2      1,1
P1     2,0        3,1      1,1
P2     0,1        2,2      2,1
Available = 4-3=1, 4-2=2 → (1,2)
求安全序列。
展开完整推演

Available = (1, 2)。逐个找 Need ≤ Available 的进程：

试 P0: Need(1,1) ≤ (1,2) ✓
  假装运行完归还：Avail = (1,2)+(1,1) = (2,3)
试 P1: Need(1,1) ≤ (2,3) ✓
  归还：Avail = (2,3)+(2,0) = (4,3)
试 P2: Need(2,1) ≤ (4,3) ✓
  归还：Avail = (4,3)+(0,1) = (4,4) = 全部资源 ✓

答：存在安全序列 <P0, P1, P2>，系统安全，可以分配。（若先试 P2：Need(2,1) 中 2 > 1，不满足——P2 必须排后面，这正是"序列"的含义。）

书写模板：每步写三样——比较式、归还后 Avail、打勾结论。按这个格式写，计算大题不给阅卷扣分的机会。

综合大题（考场同款）

限时 15 分钟 · 先自己写伪代码再展开答案对照
题目：桌上有一个盘子，每次只能放一个水果。父亲专门向盘中放苹果，母亲专门向盘中放橘子；儿子专门等吃盘中的橘子，女儿专门等吃盘中的苹果。请用信号量机制实现父亲、母亲、儿子、女儿四个进程的同步与互斥，写出信号量定义和各进程的伪代码，并说明每个信号量的含义与初值理由。
展开参考答案与推演 
semaphore plate  = 1;   // 盘子空位：既是互斥（一次一个）
                        // 也是同步（空了才能放）
semaphore apple  = 0;   // 盘中苹果数
semaphore orange = 0;   // 盘中橘子数

父亲:                        母亲:
while(true){                 while(true){
  准备苹果;                    准备橘子;
  P(plate);                    P(plate);
  苹果放入盘;                  橘子放入盘;
  V(apple);                    V(orange);
}                            }

女儿:                        儿子:
while(true){                 while(true){
  P(apple);                    P(orange);
  从盘取苹果;                  从盘取橘子;
  V(plate);                    V(plate);
  吃苹果;                      吃橘子;
}                            }

推演要点：

① "每次只能放一个"是互斥约束，但盘子放水果→有人取走是同步链条，这里 plate = 1 一箭双雕：有水果在盘时 plate = 0，另一个放水果的人自然被挡住。

② apple、orange 初值 0：初始盘中无水果，子女必须等父母先放。

③ 同步 P 在前、互斥 P 在后的纪律在本题的体现：子女先 P(apple)/P(orange) 再动盘子，若颠倒（先 P(plate)），盘中无水果时子女会抱着盘子空等——另一路放水果的人被 plate 挡住，形成死锁。

④ 阅卷给分点：信号量定义与初值理由、四段伪代码、V 的位置（取走后释放盘子）。按此三点自查。
