考点 1 · 进程与线程

三态转换是所有选择题的地基

进程实体 = PCB + 程序段 + 数据段。三态：就绪 ⇄ 运行 ⇄ 阻塞。两条单行道必须背死：阻塞 → 不能直接到运行（必须先就绪），就绪 → 不能到阻塞（没在运行谈不上等资源）。

转换触发：运行→就绪是时间片到或被更高优先级抢占；运行→阻塞是等待 I/O 或资源（主动行为）；阻塞→就绪是等待的事件发生（被动行为）。

线程：调度和分派的基本单位；进程是资源分配的基本单位。用户级线程切换不需内核介入但一个阻塞全阻塞；内核级线程切换需内核，可真并发。

例题 · 转换合法性判断
某时刻进程 P 因请求打印机而阻塞。之后打印机就绪，P 被唤醒。分别写出这两次转换的名称与触发原因，并说明 P 能否从阻塞直接转为运行。
展开完整推演

第一步：P 运行中执行"请求打印机"，资源不可用 → P 主动放弃 CPU，运行态 → 阻塞态，进入该资源的等待队列。

第二步：打印机空闲，唤醒机制把 P 从等待队列移入就绪队列：阻塞态 → 就绪态。P 此时还要在就绪队列里排队等调度，不能直接跳到运行——因为"唤醒"只解决资源问题，CPU 分配是调度程序的事。

记忆锚：阻塞 → 就绪是别人叫醒你；就绪 → 运行是调度程序选中你。中间永远隔着调度。

考点 2 · 处理机调度

周转时间计算题的套路非常固定

三个时间：周转时间 = 完成时间 − 到达时间；带权周转 = 周转 / 运行；等待 = 周转 − 运行。大题算的就是这三样。

算法要点：FCFS 利于长作业；SJF 平均等待时间最短但长作业饥饿（"饿死"）；HRRN 响应比 = (等待+服务)/服务，兼顾长短；RR 时间片过大退化为 FCFS、过小切换开销大；多级反馈队列是最通用的，新进程进最高优先级队列。

抢占 vs 非抢占：SJF 的抢占版叫 SRTF（最短剩余时间优先）；RR 天然抢占（时间片到）。

例题 · FCFS 与 SJF 对比计算
三个进程：P1 到达 0 运行 8；P2 到达 1 运行 4；P3 到达 2 运行 2。分别按 FCFS 和非抢占 SJF 计算 平均周转时间。
展开完整推演 
FCFS（按到达顺序）:
P1: 0→8     周转 8
P2: 8→12    周转 12−1=11
P3: 12→14   周转 14−2=12
平均 = (8+11+12)/3 ≈ 10.33

非抢占 SJF:
0 时刻只有 P1 → P1: 0→8   周转 8
8 时刻 P2(4) P3(2) 都在 → 先短: P3: 8→10  周转 8
P2: 10→14  周转 13
平均 = (8+8+13)/3 ≈ 9.67

结论：SJF 让短作业 P3 插队，平均周转更短；但若再来一个运行 20 的长作业，它要一直等——这就是饥饿。

书写模板：每个进程一行"开始→完成、周转 = 完成 − 到达"，最后求均值，阅卷无懈可击。

考点 3 · 信号量与 PV 操作基础

记录型信号量的值是判断一切的钥匙

信号量 S = 整型值 value + 等待队列。P 操作：value 减 1，减完 < 0 则阻塞入队；V 操作：value 加 1，加完 ≤ 0 则唤醒队头一个进程。

value 的含义：正值 = 剩余可用资源数；负值 = 绝对值就是阻塞进程数。这一条能秒杀一半的选择题。

初值：互斥信号量 = 1；同步信号量 = 可用资源数。P/V 是原语，不可中断。

铁律：同步 P 在前，互斥 P 在后——颠倒可能死锁（见考点 4 例题）。

例题 · 值的推演
信号量 S 初值为 2，当前值为 -1。等待队列中有几个进程？再执行一次 V 后 S 为多少，队列状态如何？
展开完整推演

当前值 −1 < 0 ⇒ 等待 1 个进程。执行 V：−1 + 1 = 0，加完 ≤ 0 说明仍有进程在等，于是唤醒一个进入就绪态。此后 value = 0，队列空。

注意：V 后 value = 0 不是"没资源"，而是"资源刚被唤醒者领走、无人排队"。

考点 4 · 生产者-消费者问题

大题第一模板 · 必须默写零错

标准模板（缓冲区 n 个，多生产者多消费者）：

semaphore mutex = 1;   // 互斥访问缓冲区
semaphore empty = n;   // 空位数（同步）
semaphore full  = 0;   // 产品数（同步）

生产者:                     消费者:
  生产一个产品;                P(full);
  P(empty);                   P(mutex);
  P(mutex);                   取产品;
  放入缓冲区;                 V(mutex);
  V(mutex);                   V(empty);
  V(full);                    消费产品;

三条铁律：① 两个 P 不可交换；② 两个 V 可以交换（V 永不阻塞）；③ mutex、empty、full 与进程个数无关，多对生产者消费者时 mutex 仍只需 1 个。

例题 · 初值与死锁时序
缓冲区容量 3，两个生产者一个消费者。写出初值；并推演消费者写成 P(mutex); P(full); 时缓冲区为空场景下的死锁时序。
展开完整推演

初值：mutex=1、empty=3、full=0，与进程个数无关。

t1  消费者 P(mutex) → 拿到锁
t2  消费者 P(full)  → full=-1，阻塞等产品
t3  生产者 P(empty) → 成功
t4  生产者 P(mutex) → mutex=-1，阻塞等锁
    ⇒ 消费者等"产品"，生产者等"锁"，
      锁在等"产品"的人手里。死锁。

书写要领：死锁类大题按 t1~t4 编号时序写，每行写清"谁、做什么、变成什么值"。

考点 5 · 读者-写者问题

两行灵魂代码：第一个读者 P(w)，最后一个读者 V(w)

读者优先模板：

int count = 0;            // 正在读的读者数
semaphore mutex = 1;      // 保护 count
semaphore w = 1;          // 读写互斥、写写互斥

读者:                       写者:
P(mutex);                   P(w);
if(count==0) P(w);          写;
count++;                    V(w);
V(mutex);
读;
P(mutex);
count--;
if(count==0) V(w);
V(mutex);

count 为什么加锁：两个读者同时发现 count==0，会各自 P(w)，读者间互相阻塞。写者优先：再加一个排队信号量+写者计数，让写者之后到达的读者排在写者后面。

例题 · 谁来 V(w)
R1 正在读，R2、R3 相继到达，随后 R1、R2、R3 依次退出。逐次推演 count 与 w 的变化。
展开完整推演 
      count 动作              count   w
R1到  count==0 → P(w)          0→1   1→0 持有
R2到  count==1，不 P(w)        1→2   仍 0
R3到  count==2，不 P(w)        2→3   仍 0
R1退  count-- ≠0，不 V(w)      3→2   仍 0
R2退  count-- ≠0，不 V(w)      2→1   仍 0
R3退  count-- =0 → V(w)        1→0   0→1 释放

答：P(w) 只在 R1 进入时执行一次；V(w) 只在最后退出的 R3 处执行。中间读者只动 count。

考点化：V(w) 永远跟着 count 归零走——选择题常把"第一个读者"当干扰项。

考点 6 · 哲学家进餐与死锁预防

选择题考"打破了哪个条件" · 必须对号入座

死锁四个必要条件：互斥、请求与保持、不可剥夺、循环等待。破坏任何一个即可预防。

哲学家死锁成因：5 人同时拿起左筷子 → 各等右筷子 → 循环等待。

三种解法与破坏对象：① 最多 4 人同时拿筷 → 破坏循环等待；② 奇数先左偶数先右 → 破坏循环等待；③ 一次性拿齐两根 → 破坏请求与保持。①② 下"拿一根等一根"仍在，所以不是破坏请求与保持。

预防 vs 避免：预防是静态破坏条件；避免是动态判断（银行家算法）。

例题 · 奇偶方案为何有效
P0~P4 围坐，筷子 0~4，Pi 左手 i 号、右手 (i+1)%5 号。奇数号先左后右、偶数号先右后左。推演为何不死锁。
展开完整推演

关键竞争：P0（偶，先拿 1 号）与 P1（奇，先拿 1 号）抢同一根筷子，必有一人成功一人阻塞。同理 P2 与 P3 抢 3 号。

若 5 人同时行动：P0 持 1 等 0，P4 持 0 等 4，P2/P3 之一持 3 等 2 或 4……任何时刻总有人竞争获胜，等待链无法闭合成环。环路被打断，死锁不能形成。

考点 7 · 死锁、安全状态与银行家算法

大题必考计算 · Need = Max − Allocation 是入口

三个必背关系：Need = Max − Allocation；安全 ⇔ 存在安全序列；安全状态一定无死锁，不安全状态不一定死锁。

银行家算法（避免）：每步找 Need ≤ Available 的进程，模拟归还后 Available 增大，直到全部找完——找到即存在安全序列，分配；否则拒绝。

资源分配图有环 ≠ 死锁：每类资源仅 1 个时环 ⇔ 死锁；资源多个时环路可能化简。

解除手段：剥夺资源、撤销进程。检测+解除是鸵鸟策略之外的兜底。

例题 · 银行家算法全流程
两类资源 R1、R2，总量各 4。当前（每格 R1,R2）： 
     Allocation   Max      Need
P0     1,1        2,2      1,1
P1     2,0        3,1      1,1
P2     0,1        2,2      2,1
Available = (1,2)
求安全序列。
展开完整推演 
试 P0: Need(1,1) ≤ (1,2) ✓
  归还后 Avail = (1,2)+(1,1) = (2,3)
试 P1: Need(1,1) ≤ (2,3) ✓
  归还后 Avail = (2,3)+(2,0) = (4,3)
试 P2: Need(2,1) ≤ (4,3) ✓
  归还后 Avail = (4,3)+(0,1) = (4,4) = 总量 ✓

答：存在安全序列 <P0, P1, P2>，系统安全，可分配。（P2 的 Need 是 2>1，排不了最前。）

书写模板：每步三样——比较式、归还后 Avail、打勾结论。

考点 8 · 内存管理与页面置换

地址换算 + 置换算法推演 = 大题双保险

分页地址换算：页大小 2k ⇒ 逻辑地址低 k 位是页内偏移、高位是页号；物理地址 = 帧号×页大小 + 偏移。

置换算法：FIFO 有 Belady 异常（帧变多缺页反而变多）；LRU 看过去、无异常但实现贵；CLOCK 是 LRU 的近似——循环扫描，访问位为 1 清 0 跳过，为 0 换出。

碎片：页式有内部碎片（最后一页装不满）、无外部碎片；段式相反（按逻辑单位、段长可变）。可变分区：首次/最佳/最坏适应。

有效访问时间（带 TLB）：EAT = h×(t_TLB + t_mem) + (1−h)×(t_TLB + 2×t_mem)。

例题 · FIFO 与 LRU 对照推演
引用串 1,2,3,4,1,2,5,1,2,3,4,5，3 个物理帧（初始为空）。分别求 FIFO 和 LRU 的缺页次数。
展开完整推演 
FIFO（换最早进入的帧）:
1F 2F 3F 4F(逐1) 1F(逐2) 2F(逐3) 5F(逐4)
1H 2H 3F(逐1) 4F(逐2) 5H → 缺页 9 次

LRU（换最久未使用的帧）:
1F 2F 3F 4F(逐1) 1F(逐2) 2F(逐3) 5F(逐4)
1H 2H 3F(逐5)  4F(逐1) 5F(逐2) → 缺页 10 次

答：FIFO 缺 9 次，LRU 缺 10 次——LRU 这次反而差。若帧数增到 4，FIFO 缺页 10 次（比 3 帧还多），这就是 Belady 异常。

推演技巧：画三列帧 + 每步标注替换者，LRU 还要顺手维护"最近使用顺序"。

考点 9 · 文件管理

混合索引计算是大题公式题

物理结构：连续分配支持随机访问、难扩展；隐式链接只能顺序访问；FAT 属于显式链接（表放内存）；索引分配支持随机访问，UNIX 用混合索引（直接块 + 一级 + 二级…）。

混合索引算容量：可索引块数 = 直接块数 + 盘块大小/地址长度 + (盘块大小/地址长度)² + …，再乘块大小。

空闲空间：位示图（字长 w，块号 b → 行 = ⌊b/w⌋、列 = b mod w，0 起算）、空闲链表、成组链接（UNIX）。

共享：硬链接 = 多目录指向同一 inode，计数减到 0 才删；软链接（符号链接）= 新文件存路径，可跨文件系统，原文件删除后失效。

例题 · UNIX 混合索引容量推演
块大小 4KB，每个地址项 4B，inode 含 10 个直接地址项、1 个一级间接、1 个二级间接。求单个文件最大长度。
展开完整推演 
每个索引块可装地址数 = 4KB / 4B = 1024 个
直接块:        10
一级间接:      1024
二级间接:      1024 × 1024 = 1048576
可索引总块数 = 10 + 1024 + 1048576 = 1049610
最大文件 = 1049610 × 4KB
        = 40960KB + 4MB + 4GB
        ≈ 4GB + 4MB + 40KB

易错：二级间接是 1024 × 1024 个块（先一级索引块、再二级块），别算成 2×1024。

考点 10 · I/O 管理

I/O 方式对比 + 磁盘时间计算

四种 I/O 方式：程序查询（忙等，CPU 最浪费）→ 中断（CPU 与设备并行，但每字中断一次）→ DMA（以块为单位，数据直达内存，仅传输开始/结束打扰 CPU）→ 通道。

磁盘访问时间 = 寻道时间 + 旋转延迟（平均半圈）+ 传输时间（一圈时间/每道扇区数）。

磁盘调度：SSTF 找最近（可能饥饿）、SCAN 电梯式沿一个方向扫到底再折返、C-SCAN 单向扫描更均匀。

缓冲：单缓冲处理一块 max(C+M, T)+缓冲区…记结论：双缓冲 max(T, C+M)，可连续存取；SPOOLing 用磁盘模拟独占设备为共享设备（打印机）。

例题 · 读一个扇区的时间
磁盘转速 6000 转/分，每磁道 100 个扇区，寻道时间 8ms。忽略控制器延迟，读一个扇区需要多长时间？
展开完整推演 
转速 6000 转/分 = 100 转/秒 → 一圈 10ms
平均旋转延迟 = 半圈 = 5ms
传输一个扇区 = 10ms / 100 = 0.1ms
读一个扇区 = 8 + 5 + 0.1 = 13.1ms

套路：转速换算成"一圈时间"是第一步；平均旋转延迟恒为半圈。

综合大题（考场同款）

限时 15 分钟 · 先自己写伪代码再展开答案对照
题目：桌上有一个盘子，每次只能放一个水果。父亲专门放苹果，母亲专门放橘子；儿子专门吃橘子，女儿专门吃苹果。用信号量实现四个进程的同步与互斥：写出信号量定义、初值理由和各进程伪代码。
展开参考答案与推演 
semaphore plate  = 1;   // 盘子空位：互斥 + 同步一肩挑
semaphore apple  = 0;   // 盘中苹果数
semaphore orange = 0;   // 盘中橘子数

父亲:                 母亲:
  准备苹果;              准备橘子;
  P(plate);              P(plate);
  放入苹果;              放入橘子;
  V(apple);              V(orange);

女儿:                 儿子:
  P(apple);              P(orange);
  取走苹果;              取走橘子;
  V(plate);              V(plate);
  吃苹果;                吃橘子;

推演要点：

① "每次只能放一个"由 plate=1 保证：盘中有水果时 plate=0，另一路放水果者自然被挡住——互斥与同步合一。

② apple、orange 初值 0：初始无水果，子女必须先等父母放。

③ 若子女把 P(plate) 写在 P(apple)/P(orange) 之前：盘中无水果时子女抱着盘子空等，放水果的人又被 plate 挡住 → 死锁。同步 P 在前的纪律再次体现。

④ 给分点：信号量定义与初值理由、四段伪代码、取走后 V(plate)。
