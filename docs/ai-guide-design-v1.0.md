## v1.1 变更摘要

v1.0 是纸面设计；v1.1 是把 Q1（单科打样）+ Q5（最小原型）做出来之后回填的**实测版**。四处实质性变化：

| # | 变化 | 原因 |
|---|---|---|
| **C1** | §0.1 的 D3（「模型只做结构不做结论」）由**软原则升级为硬闸门**：新增「逐字引用锚定」机制，模型给出的每条诊断必须附带原文引用，且该引用要能在题库解析里逐字匹配，匹配不上即判废 | 只有可机械验证的约束才拦得住胡说。让模型「声明自己参考了解析」是无法验证的 |
| **C2** | 体检层从 5 条判据扩到 6 条，新增 **A6 内容同源检测** | 实测发现 A1（答案自述冲突）有盲区：有两个题的解析整段属于别的题，但一个没写自述答案、另一个的自述答案恰好与标注答案一致，A1 抓不到。必须比内容 |
| **C3** | 新增第 4 个产物：**解析体检警示**（`exp-warn-*.json`），并改前端在解析旁给出提示 | 体检发现题库里有 11 道题的解析被污染，其中 6 道**解析自称的答案与标注答案冲突**。这些解析目前在界面上是**无条件展示**的 —— 学生读到的可能是明确错误的内容。这是比「没有指引」严重得多的问题 |
| **C4** | 验证分两层：产物层（`verify-guide.mts` 42 项）+ **真实渲染层**（`smoke-cdp.mjs` 新增 K/L 两节共 20 项） | 编译通过 ≠ 逻辑正确 ≠ 挂载不炸。而指引又比一般组件多一条约束：**信息披露的时机**（作答前不得出现干扰项诊断、母题骨架必须折叠）——这条只能靠真实浏览器验 |

**打样实测结果**（数据结构一科，30 题样本）：90 条模型产出 → 85 条通过校验，5 条判废，全部判废原因符合预期。产物含 50 条已锚定诊断（结论型 21 / 判据型 29）+ 35 条提问式引导，覆盖 23 个知识点、23 个母题。母题标注覆盖率 146/151 = 96.7%。

## 0 · 摘要

**结论：三个能力都能做，但必须走「离线预生成 + 运行时查表」，不能在运行时调用大模型。**

这不是保守，而是被项目的架构倒逼出来的唯一解：quiz-app 是纯静态 PWA（GitHub Pages，无服务端），浏览器直连大模型需要把 API key 放进前端，等于公开；加代理层则破坏「纯静态」这个项目最核心的性质。**把模型调用从运行时挪到构建期**，代价是一次性批处理，换来的是零运行时依赖、可人工审核、离线可用、内容可版本控制。

### 0.1 四条关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **内容按「知识点 / 母题」挂载，题目侧只存外键** | 同一知识点会被几十道题命中，按题挂载会把同一段话重写几十遍，且措辞会漂移。按知识点挂载同时解决体积、一致性与可审核性三个问题 |
| D2 | **指引数据放 `public/guide/`，按「试卷 × 科目」分片懒加载** | 不进 bundle、不拖慢首屏；改内容不需重新构建 |
| D3 | **模型只做「结构」，不做「结论」** | 让模型负责归类、抽边、写提问式提示；涉及最终判断处引用题库已有的 `explanation` / `parts[].answer`，不让模型重新表述 |
| D4 | **先做数据结构一科打样，再决定是否铺开** | 151 题 + 约 26 道应用题的体量足以暴露所有问题，成本约 ¥1 |

### 0.2 一个反直觉的结论：成本不是约束

按真实题量与 2026-10 的 API 价位测算，**全库四科一次性生成的总成本在 ¥2 ~ ¥50 之间**（详见 §6），具体取决于模型档次与是否用 Batch 半价。真正的约束有两项，都不在钱上：

1. **审核人力** —— 408 考研内容错了比没有更糟，会直接把学生带偏；
2. **解析覆盖率不均衡** —— 见 §1.2，四科的现状差异极大，不能用一套策略。

## 1 · 现状与硬约束

### 1.1 技术约束

| 约束 | 现状 | 对方案的直接影响 |
|---|---|---|
| 部署形态 | GitHub Pages 纯静态，无任何服务端 | 运行时无法安全持有 API key → 必须构建期生成 |
| 数据引入方式 | `quizStore.ts:11-15` 五个 JSON **静态 import** | 静态 import 会被 rollup 同步预加载；新增的重内容不能走这条路 |
| 构建分片 | `vite.config.ts` 的 `manualChunks` 已把 5 个 JSON 切成独立 chunk | 首屏 JS 已剥离题库，但**仍是预加载**（非懒加载） |
| 离线能力 | workbox `globPatterns` 预缓存全部 json；已有 `runtimeCaching` 规则匹配 `/assets/data-.*\.js$/` | 新增的 `guide/*.json` 需要补一条 runtimeCaching（详见 §5.1） |
| 类型预留 | `types.ts:52` 定义了 `topic?: string`（注释：关联知识点，用于错题归因） | 字段已存在但**全库使用 0 次**（实测），正是接入点，无需改 schema |
| 验证基建 | `scripts/verify-*.mts`：esbuild bundle TS → node require → 断言 → 报告写文件 | 新增内容的质量闸门可直接复用这套模式 |

数据体量现状（`src/data/`，未压缩）：

```

applied.json    332KB  (408 综合应用题 105)
politics.json   757KB  (政治 495)
```

### 1.2 数据现状：解析覆盖率极不均衡（本方案最重要的输入）

实测（用生产代码 `normalizeBank` 跑归一化后统计；`explanation` 长度 ≥ 30 字才计为「有解析」）：

| 题库 | 题数 | 有解析 | 覆盖率 | 平均解析长度 |
|---|---:|---:|---:|---:|
| 408 单选 | 596 | 156 | **26%** | 58 字 |
| 408 综合应用题 | 105 | 0 | **0%** | — （但 `parts[].answer` 有参考答案正文） |
| 政治 | 495 | 484 | **98%** | 277 字 |
| 数学一 | 218 | 207 | **95%** | 381 字 |
| 英语一 | 560 | 0 | **0%** | — |
| **合计** | **1974** | **847** | **43%** | — |

> 口径说明：`src/data/` 五个 JSON 共 **1975** 条原始条目，经 `normalizeBank` 归一化后为 **1974** 题（`math.json` 有 1 道选项为空的题被剔除，见 `normalize.ts` 的 `readOptions` 注释）。本文档一律采用**归一化后**的口径。
>
> **顺带发现一个不一致**：`vite.config.ts` 的 PWA `manifest.description` 写着「共 1946 题」，而实测归一化后是 **1974** 题——差 28，恰好是历史上一次应用题补录的量。`Home.tsx:36-40` 的注释里已经记过同类教训（「手写数字在每次扩容后都会变成谎话」），说明卡片已改为 `BANK` 现算，但 manifest 里这处没同步。**不属于本方案范围，仅记录**；若要修，是一行改动。

这张表决定了四科的价值定位完全不同：

| 试卷 | 解析现状 | AI 该干的活 | 风险 |
|---|---|---|---|
| **政治** | 98% 完善 | **只做结构化**：归类母题、抽知识点、写干扰项诊断。**禁止重写解析** | 低 |
| **数学一** | 95% 完善 | 同上 | 低 |
| **408** | 26% 有、74% 空 | 结构化 + **补解析**（价值最高，但风险也最高） | **高** |
| **英语一** | 0% | 结构化优先；解析涉及长文语境，成本与风险都高，建议先不做 | 中 |

> **推论：不能用一套策略打四科。** 政治/数学应该严格约束模型「只做结构不做结论」；408 的补解析是刚需，但必须走更严的人工抽检闸门。

### 1.3 为什么排除「运行时调用大模型」

| 方案 | 可行性 | 否决理由 |
|---|---|---|
| 前端直连 API | ✗ | API key 必须写进前端产物，等于公开；key 被刷爆是必然结局 |
| 自建轻量代理 | ✗ | 引入服务端，破坏纯静态部署；还带来运维、费用与可用性问题（proxy 挂了全站指引失效） |
| 用户自带 key（BYOK） | △ | 技术可行，但要求每个用户自己申请 key，对考研学生是不可接受的门槛；可另作「高级模式」备选，不作为主线 |
| **构建期预生成** | **✓** | **唯一同时满足零依赖、可审核、离线可用、可版本控制的方案** |

**代价必须说清楚**：内容是「静态」的——模型不能针对某个学生的具体错因现场发挥。但这一点在本项目的语境下损失很小：考研题库的知识结构封闭、答案唯一、题型高度重复，个性化价值主要来自**选择呈现哪段预制内容**（哪条前置知识、哪类干扰项），而不是现场生成措辞。这个「选择」逻辑完全可以纯本地实现（见 §5.3）。

## 2 · 三个能力的需求拆解

三者看着像一件事，技术本质差别很大。**实现难度不在「生成文字」，而在「把关系建立起来」。**

| 能力 | 技术本质 | 数据形态 | 难度 | 一次性还是持久 |
|---|---|---|---|---|
| **前置知识** | 建一张**有向无环图**（DAG） | 图结构（节点 + 边） | 中（图的规模小，难在边的准确性） | 一次性建图，其后只维护 |
| **母题** | **聚类** + 解法骨架归纳 | 表（母题 → 题目集合） | 中（粒度是成败关键） | 随题库扩充增量追加 |
| **解题指引** | 按错误路径**查表** | 键值映射（题 → 诊断） | 低（结构最简单） | 生成一次，可复用 |

### 2.1 前置知识 = 知识点依赖图

不是「给每道题配一段说明」，而是建图：`折半查找 → 需要 有序表 + 二分思想`，`KMP → 需要 前缀函数 + 字符串匹配`。

建成后能做**拓扑排序**，从而解锁刷题 App 目前最缺的能力——**归因**：

> 现在：错题本告诉你「这题错了」。
> 之后：错题本告诉你「这题错是因为 `KMP`，而你在 `KMP` 的前置 `前缀函数` 上也有失分，建议先回去补它」。

图规模不大：408 四科按「考点」颗粒度预估 **200 ~ 350 个节点**（数据结构约 60–70、计组约 70、操作系统约 60、计网约 55），边数量约为节点数的 1.2–1.5 倍。这个体量小到**可以整图打进任何一个分片**（约 30–60KB JSON），不需要图查询引擎。

**难点全在边从哪来**，三个来源建议叠加：

| 来源 | 提供什么 | 可靠性 |
|---|---|---|
| 教材目录层级（章 → 节 → 考点） | 图的**骨架**与父子关系 | 高（人工已成体系） |
| 考纲知识点列表 | **校验**：考纲有的必须有，考纲没有的要警惕 | 高 |
| 模型从「题目 + 解析」抽边 | **补充**跨章节的隐性前置（如「虚存」依赖「分页」） | 中（**必须人工过一遍**） |

> 抽错边会直接误导学生（把非前置判为前置 → 让学生去补无关内容），所以这一环**必须留人工闸门**，不能全自动上线。

### 2.2 母题 = 题型聚类 + 解法骨架

408 的题型高度模式化，母题总量预估 **100 ~ 200 个**。粒度把握是成败关键：

| 粒度 | 例子 | 评价 |
|---|---|---|
| 过粗 | 「动态规划」 | ✗ 没用，学生在问「这题该怎么下手」 |
| **正确** | 「由两种遍历序列唯一确定二叉树」 | ✓ 步骤骨架相同即归为一类 |
| 过细 | 「2011 年第 6 题的变体」 | ✗ 无泛化价值，退化成给每题配说明 |

**判据一句话：解法的步骤骨架相同，就是同一母题。**

聚类这件事恰好是大模型擅长的——把一批题丢进去问「这些题的解法的共同骨架是什么」，比让它逐题生成内容可靠得多。建议两步走：先用知识点粗分组，组内归纳骨架，再人工合并跨组同类（这一步能砍掉大量重复母题）。

### 2.3 解题指引 = 干扰项诊断 + 分级提示

两个形态，性价比差很多：

**形态 A · 分级提示阶梯**（不给答案，给「第一步看什么」）
教学价值高，但对 408 的解释题容易写飘——提示写得太泛（「仔细审题」）没用，写得太具体等于泄题。

**形态 B · 干扰项诊断**（推荐先做）
利用一个被忽略的事实：**选择题的错误选项本身就是信息**。408 单选每题 4 选项，错误选项通常是精心设计的，各自对应一个典型错误思路。学生选了 A 而答案是 B，真正有价值的反馈是「A 错在哪、你踩的是哪个坑」，而不只是「正确答案是 B」。

```
学生选 A → 显示 A 项诊断：「你踩的坑：把『队列』的存储结构与『栈』的存取顺序搞混了。
                        缓冲区需要按写入顺序读出 → 先进先出 → 队列。」

学生选 C → 显示 C 项诊断：「你踩的坑：树/图没有线性次序，无法表达『依次』。」
```

这条路径有三个优势：
1. **天然适配离线预生成**：诊断按「选项键位」索引，运行时纯查表；
2. **键位稳定**：实测 `AnswerArea.tsx` 用 `KEYS.map` 固定按 A→B→C→D 渲染，`shuffle` 开关只打乱**题目顺序**、不打乱选项顺序 → 诊断可以安全地按 `{A, B, C, D}` 索引；
3. **只针对错误项**：正确项不需要「为什么对」（那是 `explanation` 的活），所以每题只需生成 3 条诊断。

## 3 · 数据模型设计

### 3.1 设计原则

1. **不改存量 JSON 的结构**，只做**字段填充**（新增字段对新旧代码都是可选）；
2. **外键必须在主数据里**，因为错题归因要能**纯本地同步计算**（不能依赖网络取图）；
3. **重内容放独立文件**，按需加载，不拖累首屏。

### 3.2 新增文件清单

```
public/guide/                     ← 新增目录（运行时 fetch，不进 bundle）
├── kg-408.json                   知识点依赖图（图，约 40KB）
├── kg-politics.json              政治知识点图（约 25KB）
├── kg-math.json                  数学一知识点图（约 15KB）
├── mother-408.json               母题表（含解法骨架 + 陷阱库，约 60KB）
├── mother-politics.json          母题表（约 30KB）
├── mother-math.json              母题表（约 20KB）
└── diag/
    ├── 408-数据结构.json         干扰项诊断分片（约 35KB）
    ├── 408-计算机组成原理.json
    ├── 408-操作系统.json
    ├── 408-计算机网络.json
    ├── 政治-马原.json · 政治-毛中特.json · …（5 片）
    ├── 数学一-高等数学.json · …（3 片）
    └── english-完形填空.json · english-阅读理解.json
```

分片键选 **「试卷 × 科目」**而不是题目 id：用户抽题是随机的，按题分片会产生成百上千个小请求；按科目分片后，一个会话通常只需 1–3 个分片（见 §5.1）。

### 3.3 知识点图 schema（`kg-*.json`）

```jsonc
{
  "version": "1.0",
  "paper": "408",
  "generatedAt": "2026-10-13",
  "nodes": [
    {
      "id": "ds-2.3.2",                    // 科目缩写-章.节.序号（稳定，人工可读）
      "name": "二叉树的遍历",
      "subject": "数据结构",
      "chapter": "2 树与二叉树",
      "summary": "按访问根节点的次序分为先序/中序/后序……（80–150 字，用于前置知识卡片正文）",
      "prereq": ["ds-2.3.1"],              // 直接前置（有向边：prereq → 本节点）
      "keywords": ["先序", "中序", "后序", "递归"],
      "weight": 3                          // 考频权重 1–5，用于排序推荐
    }
  ]
}
```

**约束**：`prereq` 引用必须构成 DAG（无环）。校验脚本会做拓扑排序，有环直接报错（见 §8.2）。

### 3.4 母题 schema（`mother-*.json`）

```jsonc
{
  "version": "1.0",
  "paper": "408",
  "mothers": [
    {
      "id": "mt-ds-007",
      "name": "由两种遍历序列唯一确定二叉树",
      "subject": "数据结构",
      "topics": ["ds-2.3.2", "ds-2.3.3"],  // 关联知识点
      "skeleton": [                         // 解法骨架（分级提示的基础）
        "确认给定的两种序列能否唯一确定（前序+后序不行）",
        "用前序/后序的第一个（最后一个）元素定位根",
        "在中序序列中以根为界切分左右子树",
        "对左右子树递归重建，写出结构"
      ],
      "traps": {                            // 母题级陷阱库（本题型通用错误路径）
        "T-order-confusion": {
          "label": "把前序当后序用",
          "why": "前序是「根左右」、后序是「左右根」，根的位置一前一后，用错则整棵树错位"
        },
        "T-prepost": {
          "label": "误答「前序+后序可唯一确定」",
          "why": "前序与后序都只定位根、不划分左右子树，无法区分单孩子的左右归属"
        }
      }
    }
  ]
}
```

### 3.5 题目侧扩展（`src/types.ts` 增量）

只需**三个可选字段**，全部向后兼容（存量 JSON 不填即为 `undefined`，新旧代码都能读）：

```ts
interface QBase {
  // …… 现有字段不变 ……
  /** 主知识点 id（用于错题归因主线）。当前全库使用 0 次，本次正式启用 */
  topic?: string
  /** 并列知识点 id（用于弱项统计，可选） */
  topics?: string[]
  /** 母题 id（用于查解法骨架与陷阱库） */
  mt?: string
}
```

填充后的效果：

```jsonc
{
  "id": "2011-06",
  "year": 2011, "no": 6, "subject": "数据结构",
  "stem": "已知一棵有 2011 个结点的树，其叶结点个数为 116……",
  "options": { "A": "…", "B": "…", "C": "…", "D": "…" },
  "answer": "B",
  "explanation": "",
  "topic": "ds-2.3.2",
  "topics": ["ds-2.3.2", "ds-2.3.5"],
  "mt": "mt-ds-007"
}
```

**体积代价**：三个字段合计约 35–45 字节/题 × 1974 题 ≈ **80KB**（未压缩），分散在已有的 5 个数据 chunk 里，gzip 后增量可忽略。

### 3.6 干扰项诊断 schema（`diag/*.json`，分片）

```jsonc
{
  "version": "1.0",
  "shard": "408-数据结构",
  "items": {
    "2011-06": {
      // 只用填「非正确项」；正确项由 explanation/骨架承担
      "A": { "trap": "T-prepost", "why": "把「只有一个孩子」的情形当成可唯一确定，忽略了左右归属" },
      "C": { "why": "把叶结点数当成结点总数代入" },
      "D": { "trap": "T-order-confusion", "why": "混淆了树与二叉树的孩子表示法" }
    }
  }
}
```

**两级回落设计**（体积与精准度的折中）：
- 题目级 `items[qid][key]` 存在 → 用它（最精准）；
- 不存在 → 回落到母题级 `traps[母题].traps[trapId]`（通用但覆盖全）。

实测每题 3 条诊断、每条约 60 字 → 全库约 **17 万字 / 350KB**（未压缩），按 14 个科目分片后每片 **10–40KB**。**并且题库新增题目时，没有专属诊断的题会自动回落到母题级内容，不会出现「新题没指引」的空缺。**

```
                  ╚═══════┬═══════╝         │

                  ╚═══════════════╝  └──────────────┘
```

**关键设计：阶段 2 必须在阶段 4 之前，且中间有闸门 A。** 因为母题聚类与诊断生成都建立在知识点标注之上——如果知识点标错了，后面全部内容会沿着错误的分组生成，返工成本是整条管线。

### 4.2 脚本组织

```

├── 2-tag-questions.mjs       题目 → topic/topics 外键（写回 src/data/*.json）
├── 3-cluster-mothers.mjs     母题聚类 + 骨架归纳 → mother-*.json

```

脚本形态与现有 `scripts/add-math-2024-2025.mjs` 一致（`.mjs` + 原生 `node`），不引入新依赖。

### 4.3 阶段 1 · 建知识点图谱

| 项 | 设计 |
|---|---|
| **输入** | 考纲/教材目录整理的骨架（人工），约 250 行 |
| **模型任务** | ① 补齐每个节点的 `summary`（80–150 字）；② 抽取 `prereq` 跨章节边 |
| **输出** | `kg-*.json` |
| **批处理** | 按章分组，每章一次调用（408 四科共约 26 章 → 26 次调用） |
| **模型选型** | 结构化任务，便宜档够用（见 §6） |
| **人工闸门** | `prereq` 边**必须逐条过**（约 300–500 条边，1–2 小时可完成） |

**Prompt 要点**：给模型**全部节点 id 的白名单**，要求只能引用白名单内的 id；输出后逐条校验，不合法即回退重生成。空手让模型「自己编知识点」是幻觉的重灾区。

**DAG 校验**：拓扑排序，有环则报错并输出环路径，人工修骨架（通常是「A 是 B 的前置，B 又是 A 的前置」这类粗心）。

### 4.4 阶段 2 · 题目 → 知识点标注

| 项 | 设计 |
|---|---|
| **输入** | 每题 `stem` + `options`（实测平均 168 字符/题） |
| **模型任务** | 从白名单中选 1 个主知识点 + 0–2 个并列知识点 |
| **输出** | 写回 `src/data/*.json` 的 `topic` / `topics` 字段 |
| **批处理** | **每批 20 题**（约 3.4K 字符/批 × 99 批）；白名单放 system prompt 并启用**缓存命中** |
| **模型选型** | 便宜档 |
| **幂等** | 状态文件记录 `{qid: stemHash}`，只处理新增或题干变更的题 |

**这一阶段的成本优化关键**：把约 3KB 的知识点白名单放进 system prompt，配合 **prompt caching**（缓存命中价约为未命中的 2%–5%），99 次调用里白名单部分几乎免费。

### 4.5 阶段 3 · 母题聚类

| 项 | 设计 |
|---|---|
| **输入** | 按知识点分组的题目集合（含已有 `explanation`，供模型判断解法） |
| **模型任务** | 组内归纳解题骨架 → 提出母题候选；标注题型陷阱 |
| **输出** | `mother-*.json` |
| **批处理** | 每个知识点一次调用（约 250 次） |
| **人工闸门** | **跨组同类合并**必须人工做（模型只看到组内，看不到「这两组其实是同一个母题」） |

**为什么要人合并**：模型按知识点分组工作，但同一母题可能横跨多个知识点（如「Cache 命中率计算」同时涉及「Cache 映射方式」与「平均访存时间」）。不合并的后果是同一个母题被拆成 3 份，指引质量断崖式下降。

### 4.6 阶段 4 · 干扰项诊断生成

| 项 | 设计 |
|---|---|
| **输入** | 单题（stem + 4 选项 + 答案 + 母题骨架 + 已有解析） |
| **模型任务** | 为**每个非正确选项**写出「它对应哪个错误思路、为什么错」 |
| **输出** | `diag/*.json` |
| **范围** | **仅单选题**：408 596 + 政治 240 + 数学一 123 = **959 题**（英语一 560 道单选暂不纳入，理由见 §8 M4；多选/填空/应用题的干扰项语义不同，二期再说） |
| **批处理** | 每批 10 题 |
| **模型选型** | 需要学科理解，用中档；408 建议用最强档 |
| **约束** | 硬规则见下 |

**四条硬约束（写进 prompt + 输出后校验）**：
1. **禁止复述答案**：不得出现「正确答案是 X」「所以选 X」——正确性由 `explanation` 承担，诊断只说错误路径；
2. **每条 ≤ 80 字**：长诊断学生不看；超长直接判不合格重生成；
3. **必须指向具体错误**：「不仔细」「概念不清」这类空话判不合格（用黑名单词表过滤）；
4. **引用 `trap` 时必须存在于母题陷阱库**，否则回落到只输出 `why`。

### 4.7 幂等与增量

题库会继续扩充（历史上已扩过 P5 英语一 560 题），管线必须能增量续跑：

```jsonc
// scripts/.ai-guide-state.json（不进版本库，加入 .gitignore）
{
  "2-tag":        { "2009-01": "a3f2…", "2009-02": "9c1b…" },   // qid → 题干 hash
  "4-diagnostics":{ "2009-01": "7d4e…" },                        // qid → 输入 hash
  "meta": { "kgVersion": "1.0", "runAt": "2026-10-13" }
}
```

规则：**hash 不变则跳过**。题干被修正过（题库维护中会发生）→ hash 变 → 自动重跑该题。这样一次全量生成之后，日常维护只需处理新增部分，成本趋近于零。

### 4.8 质量闸门

| 闸门 | 时机 | 做法 | 不合格则 |
|---|---|---|---|
| **A** | 阶段 2 后 | 分层抽检每题型的 5%（约 50 题）人工核对知识点标注 | 调整 prompt → 重跑受影响批次 |
| **B** | 阶段 4 后 | ① 自动校验（结构、长度、黑名单词、trap 引用有效性）② 人工抽检 3% | 不合格条目重生成，仍不合格则**剔除该条**（回落母题级） |
| — | 上线后 | 保留「内容有误」反馈入口（可复用现有缺图上报的交互模式） | 收集反馈 → 修数据 → 增量重发 |

> **原则：宁缺勿错。** 任何一条诊断无法通过校验时，正确动作是**删掉它让用户回落到母题级内容**，而不是「差不多就发」。408 的解析错了会把学生直接带偏，这比「这条题没有专属诊断」严重得多。

## 5 · 运行时集成设计

### 5.1 分片加载策略

**不走 `src/data/` 静态 import 的原因**：静态 import 会被 rollup 同步预加载（现有 5 个数据 chunk 就是这样），新增约 0.5MB 指引数据会让首屏回到 2.5MB 量级，与项目既有的性能优化方向（vite.config.ts 里那段注释）直接冲突。

**改放 `public/guide/`，运行时 `fetch()` 按需取**：

```js
// 概念示意：按需加载 + 会话级预取
async function ensureGuideShard(paper, subject) {
  const key = `${paper}-${subject}`
  if (guideCache.has(key)) return guideCache.get(key)
  const p = fetch(`guide/diag/${encodeURIComponent(key)}.json`)
    .then(r => r.ok ? r.json() : null)
    .catch(() => null)              // 失败静默降级，绝不影响答题
  guideCache.set(key, p)            // 存 Promise，天然做并发合并（避免重复请求）
  return p
}
```

**并发合并**这一点要特别注意：会话里连续几题都属于同一科目时，朴素的 `if (cache) ... else fetch()` 会让多个调用者同时发现缓存为空、各自发一次请求。**缓存里存 Promise 而不是结果**是解决它的标准手法（这也是同项目的 fx-dashboard 踩过的坑，见其 `_coalesce` 实现）。

**PWA 缓存**：现有 workbox `runtimeCaching` 只匹配 `/assets/data-.*\.js$/`，需补一条规则，让指引分片在首次访问后离线可用：

```js
{
  urlPattern: /\/guide\/.*\.json$/,
  handler: 'StaleWhileRevalidate',      // 有缓存先给，后台更新
  options: { cacheName: 'quiz-guide', expiration: { maxEntries: 40, maxAgeSeconds: 60*60*24*30 } },
}
```

**会话预取**：用户进入练习页时，筛选条件（试卷 + 科目）已确定 → 可提前把这 1–3 个分片取好，实际体验是「点开解析时内容已经在了」。随机练习模式下预取该试卷全部分片（408 为 4 片 ≈ 120KB）。

### 5.3 归因闭环（纯本地，不联网）

这是本项目最值得做的一块，因为**数据其实已经齐了**：`AttemptRecord` 里存了每题的 `correct` 与 `ratio`。

```js
// 概念示意：本地聚合，无网络请求
function weakTopics(window = 90) {
  const since = Date.now() - window * 864e5
  const agg = new Map()                       // topicId → {try, miss, weight}
  for (const r of history) {
    if (r.ts < since) continue
    const q = getQuestion(r.qid)
    if (!q?.topic) continue
    const a = agg.get(q.topic) ?? { try: 0, miss: 0, subject: q.subject }
    a.try++
    if (!r.correct) a.miss += (1 - (r.ratio ?? 0))   // 应用题部分得分也计入
    agg.set(q.topic, a)
  }
  return [...agg].map(([id, a]) => ({ id, rate: 1 - a.miss / a.try, ...a }))
      .filter(x => x.try >= 3)                // 样本太少的先不推
      .sort((a, b) => a.rate - b.rate)
}
```

闭环三步：**做错题 → 查 `topic` → 沿 `prereq` 往上找断点 → 推荐该补的前置（挂载点 3）**。

> 补一个容易忽略的细节：沿依赖图上溯时不要无限上溯（会推到「数学基础」这种没用的地方），**建议限制在上溯 2 层**，并且优先推荐**本身也测出薄弱的前置**（`rate` 低）——只有「你弱，而且它是这题的前置」才值得推。

### 5.4 降级设计（必须做）

指引是**增强**，不是主功能。任何一环失败都不能影响答题：

| 失败点 | 行为 |
|---|---|
| 分片 fetch 失败 / 404 | 静默失败，卡片上**不显示**指引区（不留空白、不报错、不阻断作答） |
| 题目没有 `topic` | 隐藏「前置知识」入口，其余照常 |
| 题目没有 `mt` / 诊断 | 回落到母题级陷阱库；再没有则隐藏 |
| `kg` 加载失败 | 「薄弱知识点」卡片整体隐藏 |
| 离线 | workbox 已缓存的分片照常可用（SWR 策略） |

实现上建议把「指引数据是否可选」做成一个显式分支（例如 `guideState.ready === false` 时直接不渲染），**避免出现「转圈圈的指引区」**——这正是同项目 fx-dashboard 花了一整轮才修掉的那类「装死」问题。

**叠加返工余量**（prompt 调试、抽检不合格重生成、母题合并后重跑）——按 3~5 倍计，全量仍落在 **¥3 ~ ¥130** 区间。

**单科试点（数据结构，151 单题 + 26 应用题 + ~65 知识点）**：输入约 260K、输出约 36K → 在上述任一款上都是 **不到 ¥1**。

### 6.4 结论：钱不是约束，人力才是

| 成本项 | 量级 | 说明 |
|---|---|---|
| **API 费用** | **¥1 ~ ¥30** | 甚至低于调试 prompt 时消耗的注意力成本 |
| **人工审核（单科试点）** | **约 3 ~ 4 小时** | 边审核 60 条 + 标注抽检 8 题 + 诊断抽检 15 条 + 母题合并 |
| **人工审核（408 全科）** | **约 10 ~ 15 小时** | 边 300–500 条 + 抽检 + 母题跨组合并 |
| 后续增量维护 | 接近 0 | 幂等状态只处理新增题，新增 100 题成本 < ¥1、人工 < 30 分钟 |

**所以设计的重心应该放在「降低审核成本」上，而不是「降低 token 成本」**——例如把诊断写得短（≤80 字，一屏可扫完）、把待审条目按置信度排序（先审低置信的），都比省几毛钱 API 费重要得多。

|---|---|---|---|
| R1 | **结论写错**（尤其 408 补解析） | 高 | 见 §4.6 四条约束；**只让模型做结构、不做结论**；408 补解析单独走最强模型 + 逐条人工过 |

| R7 | **首屏体积回升** | 中 | 指引数据走 `public/`，不进 bundle；分片后单次最多 40KB |
| R8 | **考纲 / 教材改版导致内容过时** | 低 | 数据带 `version`；状态文件支持按知识点 id 定向重跑 |
| R9 | **学生产生思考惰性**（直接看提示） | 低 | 分级提示**默认折叠**；干扰项诊断**作答后才出现**（无论对错 —— 答对也值得知道其余三项错在哪，但绝不在作答前泄露）；不做「一键看答案」 |

**R1 和 R5 是仅有的两个「会造成实际伤害」的风险**，其余都是体验或成本问题。这两个都在设计上留了强制人工闸门。

## 10 · 【v1.1 新增】解析锚定机制

> 本节回应 v1.0 遗留的最大风险：**怎么保证模型不把「解析」这唯一可信来源读歪、甚至自己编结论。**
> 结论是：把「不许胡说」从提示词里的软要求，变成一道能机械验证的硬闸门。

### 10.1 问题的真实形态（实测，不是假设）

体检数据结构 151 题（其中 40 题有 ≥30 字解析）后发现，**「有解析」不等于「解析可用」**：

| 污染类型 | 题数 | 实例 |
|---|---|---|
| **解析自称的答案与题库标注答案冲突** | 6 | `2023-01` 标注 D、解析写「故本题的正确选项为 C」 |
| **解析整段属于另一道题（内容错位）** | 2 | `2023-11` 问「快排枢轴」，解析讲的是「CPU 主频 1.5GHz 的执行时间」 |
| **PDF 提取残留（C1 控制字符 / 非法 Latin-1）** | 2 | `2023-06`、`2023-09` 的解析与选项里混入 `U+0080`–`U+009F` |
| **第三方水印混入选项** | 1 | `2011-07` 的 D 选项末尾带站点推广语 |

**合计 11/40 不可用，只有 29 题可作为锚定源。**

这个数字改变了方案的走向。原本的设想是「拿解析当参考、让模型写得更好」；实测之后必须改成：**解析要么被逐字引用、要么就完全不给结论**。因为把一段自称答案 C、而题目答案是 D 的解析交给模型，模型会「忠实地」把它继承、放大、并用结构化的形式固化下来 —— 那比不生成更糟。

顺带发现一个**独立于本功能的老问题**：这 11 道题的解析目前在练习页上是无条件展示的。学生答完题点开解析，读到的是错的。这与 AI 指引无关，但优先级更高，已在 §10.6 单独处理。

### 10.2 核心机制：两条互斥路径 + 逐字引用

```
                       ┌───────────────┐
   题库解析 ──► 体检 ──►│ usable?       │
                       └───┬───────┬───┘
                        是 │       │ 否
                           ▼       ▼
                    路径 G        路径 P
              有可信解析          无可信解析
                           │       │
              ┌────────────┴──┐  ┌─┴──────────────┐
              │ 必须给 evidence │  │ 只能给 probe    │
              │ .quote（逐字）  │  │ （提问式引导）  │
              └────────┬───────┘  └─┬──────────────┘
                       ▼            ▼
                  verifyQuote   禁止出现结论词
               归一化后 substring   （因为/所以/因此/错在/
               匹配不上 → 判废      说明/应该是…）
                       └─────┬──────┘
                             ▼
                     validateShard 汇总
                             ▼
                     产物（静态 JSON）
```

**为什么是「逐字引用」而不是「让模型声明它参考了解析」。** 后者无法机械验证 —— 模型说「我依据原文」，你没有任何办法证伪。而逐字引用可以：它最终是一个**字符串包含判断**，零成本、零假阳性（引用确实在原文里就是确实在）、可离线回归。这是把一个软约束变成硬闸门的唯一实用手段。

归一化（`normalizeForMatch`）在这一步很关键：匹配前要去掉空白、统一全半角标点、剥离 LaTeX 包裹。**注意 LaTeX 命令必须替换成语义等价文本而不是删除** —— 早期版本直接删掉 `\log`，导致 `O(n\log_2 n)` 被归一化成 `o(n2n)`，一个**完全正确**的引用反而匹配失败。引用校验里，漏判（把对的判成错的）比误判更危险：误判只是少一条诊断，漏判会让整条机制失效。

### 10.3 证据强度分两级（这一条是打样中补上的）

写样张时发现了 v1.0 漏掉的一个关键区分：**多数解析只论证了正确选项，对三个干扰项并没有直接说明。**

以 `2020-08`（AOE 关键路径）的解析为例，全文只有一句定义：「关键路径：在 AOE 网中，从源点到汇点的所有路径中具有最大路径长度的路径」。让学生选错 A（「边数最多」）的模型，可以从这句定义出发推出 A 不成立 —— 引用是真的（确实逐字在原文里），但**从定义到「A 错在哪」这一步推理是模型做的**。这和「解析里直接写了 A 错在哪」显然不是一个可信等级。

不区分这两者，「已锚定 18 条」这个数字会给人虚假的安全感。所以：

| `evidence.kind` | 含义 | 处置 |
|---|---|---|
| `conclusion` | 解析**直接说明**了该错误路径，模型只是搬运 | 引用通过即可用；不进人工抽检名单 |
| `criterion` | 解析只给了**定义或判定标准**，诊断由模型据此推出 | 引用通过才可用，**且必须进人工优先抽检名单** |

两级都要求逐字命中原文，差别只在「从引用到诊断」这一步由谁完成。实测分布：**结论型 21 条 / 判据型 29 条** —— 判据型占 58%，与预期一致。另外 `kind` 只允许这两个值，模型不得自创强度等级。

### 10.4 体检闸门（6 条判据，按置信度分级）

| 代号 | 判据 | 置信度 | 处置 |
|---|---|---|---|
| A1 | 解析自称的答案与标注答案冲突 | 零假阳性 | 硬隔离 |
| A2 | 含 C1 控制字符 / 非法 Latin-1（PDF 抽取残留） | 高 | 硬隔离 |
| A3 | 第三方水印 / 站点推广语 | 高 | 剥离后可用（只污染局部） |
| A4 | 引用了不存在的配图 | 中 | 标记，生成时禁引该句 |
| A5 | 特征数字与题干零重合 | 弱 | **不参与判定**，只用于人工复核排序 |
| **A6** | **解析与题干内容不同源** | 中 | **硬隔离**（v1.1 新增） |

**A6 是这次补上的关键一环。** A1 只能抓「解析自己说了答案、且与标注不符」的错位，实测有两个题从它眼皮底下走过：

- `2023-03`：题问三元组表还需保存什么，解析讲的是哈夫曼编码的加权平均长度 —— 解析里根本没写自述答案，A1 无从判断；
- `2023-07`：题问非空 B 树的叙述，解析讲的是 600 元素有序表的折半查找比较次数 —— 更巧的是它自述的答案 B **恰好与本题标注答案一致**，连「冲突」都算不上。

这两题的解析文本属于别的题，光看答案字段永远抓不到，只能比内容。

A6 的做法是**特征词 bigram 重合度**：把题干+选项与解析各切成中文 2 字滑窗（丢掉含停用字的）+ 拉丁整词，算重合数。阈值不是拍脑袋，是在 32 道可锚定题上量出来的：

| 题号 | shared | 题干特征词数 | ratio | 人工判定 |
|---|---|---|---|---|
| `2023-03` | 0 | 25 | 0.000 | **真错位** |
| `2023-07` | 3 | 31 | 0.048 | **真错位** |
| `2020-10` | 0 | 14 | 0.000 | 解析只写了 B 树的定义就断了，没回答题目 —— 同样不该作结论来源 |
| `2014-02` | 13 | 24 | 0.092 | 真同源（解析 141 个特征词，措辞与题干差别大） |

取 `shared ≤ 3 且 ratio < 0.10 且 题干特征词 ≥ 12`：命中上述 3 题，与 `2014-02`（0.092）之间留有余量。题干特征词少于 12 时返回 `undecidable` 而不是硬判 —— 例如 `2014-11`（题干与选项几乎全是数字，只有 5 个特征词），这种题上用这个信号纯属噪声。

**误伤与漏判的代价是不对称的**，阈值因此宁可偏严：误伤 = 这道题降级成「只给提问式引导」，学生少看一句解释；漏判 = 把另一道题的解析逐字引用成这道题的权威结论，学生被**明确误导**。前者可接受，后者不可接受。

一个实现细节：A6 只在前面的硬信号都没报警时才升级 `status`。`2023-11` 同时满足 A1（自述答案 C ≠ 标注 D）与 A6（内容错位），此时报 `answer-conflict` —— 它是零假阳性的硬证据，信息量比 `content-mismatch` 更大。判定理由要保留置信度最高的那一条。

### 10.5 为什么路径 P 不是「什么都不给」

无解析的题占多数（408 数据结构 151 题里 122 题无解析）。如果这些题只能拿到一句「本题暂无解析」，指引的价值就没了。路径 P 的实际分工是：

- **题级引导**由模型写（需要理解具体题目，但只允许提问、禁止结论）；
- **母题级陷阱**来自人工编写的陷阱库（可信知识，不走模型，直接展示）。

也就是把「模型能做的」和「人已经确认的」分开。38 个母题共带 100+ 条陷阱，每条都写了「为什么会踩」—— 这部分内容是**人工作者**产出的，与模型的提问式引导互补。

关于 Q2（要不要用 AI 补解析）：本方案选择**暂不补**。补解析是从「利用已有内容」跳到「生产新内容」，风险量级完全不同 —— 前者错了最多少一条诊断，后者错了直接给学生一段看起来权威的错误讲解。在 A1–A6 这套闸门只跑通了「校验」而没跑通「新内容质量评估」之前，不宜进入。真要补，需要先有一套独立的评估方法（比如用同知识点下其他题的解析做交叉验证），那是另一个课题。

### 10.6 附带产物：解析体检警示（v1.1 新增，优先级最高）

§10.1 提到的 11 道被污染解析，目前**在练习页上是无条件展示的**。这比「没有 AI 指引」严重：学生会把 `2023-01` 那句「故本题的正确选项为 C」当真（实际答案是 D）。

因此管线额外产出一个 `public/guide/exp-warn-408-ds.json`（1.6KB，11 条），前端在解析旁给出提示：

> **解析未通过校验**：解析自称答案 C，与题库 answer=D 冲突（「故本题的正确选项为 C」，位置 187）
> （本题的题库解析存在疑似错误，已不作为结论来源；上面的解析仅作参考，请以教材为准。）

这是一个**独立于指引功能的修复**，但它来自同一次数据体检，成本几乎为零，收益直接。**建议在任何后续工作之前先把它上线。**

### 10.8 提示词侧的关键设计：明确授权「留空」

校验器只能事后剔除不合格条目。如果提示词让模型以为「必须填满三个干扰项」，模型就会为了填满而编造引用 —— 校验器把它们全部剔掉，于是白花一轮调用，产出还是空的。

所以提示词的第一要务不是「要求正确」，而是**明确允许并鼓励留空**：

> 如果你在参考解析里**找不到**能支撑某条诊断的句子，就把该选项的值写成 null。
> **留空是允许的、被期待的；编造是不可接受的。** 悬空比错误好。

同理，对 `conclusion` / `criterion` 的标注也做了诚实激励：

> 诚实标注 criterion 不会让条目作废，只会让它进入人工优先复核名单。
> 把 criterion 虚标成 conclusion 属于学术不诚实，一经比对引用与诊断的语义不匹配即判废，后果比留空严重得多。

### 10.9 打样实测：判废明细（全部符合预期）

30 题样本产出 90 条，判废 5 条：

| 条目 | 判废原因 | 性质 |
|---|---|---|
| `2011-02/D` | 引用未能在解析原文中逐字匹配：「e有四个可插入位置」 | 编造引用 → 拦下 |
| `2011-04/A` | 空话黑名单命中「概念不清」 | 空话 → 拦下 |
| `2012-11/A` | 复述答案（命中 `/正确答案\s*(?:是\|为)/`） | 泄露答案 → 拦下 |
| `2020-08/D` | 引用被改写（原文「最大路径长度」写成「最大路径路径长度」） | **差一个字就拦下** —— 最能说明逐字引用的作用 |
| `2013-03/B` | 路径 P 下出现结论词「意味着」 | **误伤**：此处是在复述平衡因子的定义 |

最后一条是已知代价，记录在案：路径 P 的结论词禁令有意做得钝（宁可错拦），所以复述定义类的措辞也会被拦。这一条不打算修 —— 修改它需要区分「复述定义」与「对选项下结论」，而这恰恰是机械手段做不到的那类判断。

### 10.10 一个实现期发现的 bug（值得记下来）

增量复跑时发现产物里的 `stats` 会被**本次运行**的统计覆盖：第二遍跑因为全部命中增量、本次产出 0 条，于是产物统计被写成全 0，前端据此显示「0 条诊断」。

修法是分开记两本账：`stats` 从**合并后的产物**算（累计口径），`lastRun` 记本次运行。**「产物统计」与「本次运行统计」是两件事** —— 任何做增量管线的场景都容易踩这一脚。
