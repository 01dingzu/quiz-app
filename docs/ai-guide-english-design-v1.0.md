## 0 · 摘要

### 0.1 三条关键决策

| # | 决策 | 理由（详见） |
|---|---|---|
| **D1** | **锚定源换成共享长文原文**，而不是给英语一补解析 | 实测：英语一 560 题 `explanation` **全部为空串（0/560）**，没有可锚定的解析；而 70 篇长文共 17.3 万字符、**零污染**（0 控制符 / 0 乱码 / 0 断裂），是题库里最干净的一份语料。补解析是「再生成一份可能错的语料」，锚原文是「引用一份已经对的语料」——风险量级差一个数量级（§1.3） |
| **D2** | **证据类型由干扰项陷阱类型强制决定**，模型不得自选 | 408 侧模型只需在 `conclusion`/`criterion` 之间诚实标注；英语侧把这一步进一步收紧：**陷阱类型 ↔ 证据类型一一绑定**，模型说「无中生有」就必须交出反向可伪证的证据，不能挑一个容易通过的证据类型蒙混（§3.1） |
| **D3** | **调度单位从「题目」改为「材料」** | 560 题只挂在 70 篇材料上（完形 20 题/篇、阅读 5 题/篇）。按题调度会把同一篇原文重复发 5–20 次；按材料调度使**原文每篇只发一次**，请求数从 560 降到 **112**，并让模型能看到同篇的 5 道题，避免对同一句话给出互相矛盾的诊断（§5.3） |

### 0.2 一个反直觉的结论：英语一比 408 更好做，但难点换了位置

直觉上「英语没有解析」是最大的障碍。实测后**恰好相反**：

| 维度 | 408 数据结构 | 英语一 | 说明 |
|---|---|---|---|
| 可锚定语料 | 40/151 题有解析，其中仅 **29 题可用** | **70/70 篇材料可用** | 英语的语料可用性是 408 的 **6 倍**（按题算：560/560 vs 29/40） |
| 语料污染 | 11 题污染（6 题解析自称答案与标注冲突、整段错位、PDF 控制符、水印） | **0 篇污染** | 控制符 / 乱码 / 连字符断裂 / 制表符 **全部为 0** |
| 文本体检 | 需要 6 条内容性判据（A1–A6）才拦得住 | **内容性判据全部失效**，只能用结构性判据 | 见下方「否定发现」 |
| 真正的新难点 | 判断解析可不可信 | **排版符号**（418 处弯引号会让正确引用 100% 被判废）、**完形空位标记**、**模型可能把"选项"当成"原文"来引用** | §3.3 / §3.4 / §3.5 |

**一条否定发现（实测推翻了照搬 A6 的打算）**：408 侧的 A6「内容同源检测」（用题干+选项与解析的实词重合度判断解析是否错位）**在英语上完全不可用**：

- 完形填空的选项是**单个单词**（中位 1 词），与材料的实词重合率**天然为 0**——按 A6 的阈值会把 **280 道完形题全部误判为错位**；
- 阅读的 280 题里，正确选项有 **28.6% 与原文零原词重合**（正确答案本就靠同义替换表达），重合度不是信号。

**这条发现直接改变了 §3.6 的设计**：英语的材料体检只保留结构性判据，内容性判据一个都不要。

### 1.3 为什么不能照搬数据结构的「解析锚定」

数据结构那套机制的分流逻辑是：

```
解析可用 → 路径 G：必须逐字引用解析原文
解析不可用 → 路径 P：只提问，不下结论
```

英语一如果照搬，**560 题全部走路径 P**（解析 100% 为空），产出一堆「请你自查」而无任何题级实质内容——等于没做。补解析也不可取：

| 方案 | 做法 | 风险 |
|---|---|---|
| A. 让模型补写解析，再锚定它 | 先让模型生成 560 条解析，再按 408 的方式锚定 | **本末倒置**：解析本身就是模型生成的，锚定它等于「让模型的第一次输出约束第二次输出」，两次都错就锁死；且生成解析属于「做结论」，正是 §0.1 的 D3 想避开的 |
| B. 把原文当锚定源（**本方案**） | 模型必须引用**原文逐字片段**支撑每条诊断 | 原文是**人工/官方来源的既有语料**，不是模型产物；引用它属于「搬运证据」，不是「生产结论」 |
| C. 只做知识点/母题，不做题级内容 | 完全不出题级指引 | 保守但价值有限——英语最大的痛点恰恰是「这四个选项到底差在哪」 |

选 **B**。它不是妥协方案：英语阅读的解题本质就是**定位与比对**，而「把定位句指出来」正是锚定机制最自然的形态。

## 2 · 需求拆解

### 2.1 英语的「可信来源」是原文，而它有个 408 没有的性质

| | 408 数据结构 | 英语一 |
|---|---|---|
| 可信来源字段 | `explanation`（每题一份，短，可能错） | `materials[materialId]`（每篇一份，长，可信） |
| 来源与题目的关系 | **1 : 1** | **1 : N**（完形 1:20，阅读 1:5） |
| 来源在运行时是否已加载 | 否（诊断产物的锚定源是原始解析文本，前端不展示它做证据） | **是**（`MATERIALS` 已在内存，长文就在题卡上方展示） |
| 因此可以做的事 | 引用解析 → 学生可核对 | 引用原文 → **学生可以直接在屏幕上方找到这句话** |

最后一行是英语独有的优势：**引用可当场核对**。所以英语侧的 UI 不该只给一段引用文本，而应该给「跳到原文那一句」的能力——本方案用「给出引用 + 段落号」实现，不改长文渲染（§6.1）。

### 2.2 阅读与完形的语境形态不同（实测决定）

| 项 | 阅读理解 | 完形填空 |
|---|---|---|
| 每题挂载 | 5 题/篇 | 20 题/篇 |
| 题干形态 | 完整英文问句 / 不完整句（如 `Newspaper reviews in England before World War II were characterized by`） | **「第 N 空」**——共 20 种取值，**没有实际文字** |
| 选项形态 | 短名词短语（归一化长度中位 **32**，p5 = 10） | **单个单词**（中位 1 词） |
| 解题依据 | 原文的**某一句**（定位句） | 空位**所在句/邻近片段** |
| 空位标记 | — | 正文内 `{{1}}`…`{{20}}` |

**两个直接后果**：

1. **完形的诊断提示词必须把「空位所在句」当作题干喂进去**——题目自带的 `stem` 只是「第 3 空」，没有任何语境，模型无从下手；
2. **完形空位所在句长度实测**：min/p25/中位/p75/max = **30 / 112 / 140 / 185 / 496** 字符；而且 **218 / 280 题（77.9%）的所在句里含 2 个以上空位**。所以「引用那一句」往往**同时覆盖两个空白**，不足以唯一定位——必须允许引用**连续片段**（含空位句的窗口），并在校验里强制该片段覆盖目标空位（§3.5）。

### 2.3 题型分类 = 英语的母题

英语没有 408 那种「解法步骤骨架」式的母题，但有更成熟的对应物：**题型**。它决定解题骨架（定位范围、比对方式、排除策略），也决定干扰项陷阱库。

| 层 | 408 数据结构 | 英语一 |
|---|---|---|
| 知识点图 | 概念依赖（栈→表达式求值→中缀转后缀） | **解题能力点**依赖（题型识别→回文定位→同义替换识别；指代关系→态度色彩词） |
| 母题 | 题型聚类 + 解法骨架（38 个） | **题型**（阅读约 15 类 + 完形 5 类） |
| 陷阱库 | 每个母题一组陷阱 id | **干扰项类型**（偷换概念 / 正反混淆 / 张冠李戴 / 无中生有 / 过度推断 / 以偏概全 / 答非所问） |

**关于题型分布的一个诚实说明**：探针用正则对题干做了粗分类，得到「段落/行号定位类 39.6% / 其他细节类 38.9% / 主旨类 7.5% / 态度类 4.6% / 例证类 3.9% / 推断类 2.9%」，但**这个分布不可信、本方案也不打算用它**——正则区分不了「推断题」与「带 suggest 的细节题」，且 38.9% 落进了兜底桶。它能说明的只有一件事：**细节类占大头，题型粒度不能太细**。正式标注必须走「关键词规则 + 人工 overrides」（复用 `scripts/ai-guide/lib/tag.mjs`），并在 M1 实测歧义率后再定粒度（§10 · Q4）。

## 3 · 锚定机制设计（本文档的核心）

> 本节回应一个问题：**「不许胡说」在英语侧长什么样？**
> 408 的答案是「必须逐字引用解析」。英语的答案多一步：**连"引用什么"都必须由论点类型决定。**

### 3.1 四种证据类型，且与陷阱类型强制绑定

英语侧的 `evidence.kind` 词汇表（扩展 408 的 `conclusion`/`criterion`）：

| kind | 适用 | 语义 | 机械校验（全部必须通过） |
|---|---|---|---|
| `locate` | 阅读 · **正确选项** | 原文中支撑正确答案的那一句 | ①`normalize(quote) ⊆ normalize(材料原文)` ②归一化长度 ≥ 25 ③**不得**同时是某选项的子串 |
| `contrast` | 阅读 · 干扰项 | 原文里**被该干扰项扭曲/反转/换主体**的那一句 | 同上 |
| `context` | 完形 · 干扰项 | 含目标空位的原文连续片段 | ①②③ + ④**必须覆盖 `{{N}}`** + ⑤原始长度 ≤ 400 字符 |
| `absent` | 阅读 · 干扰项 | 该干扰项的**关键措辞在原文中根本不存在** | ①`normalize(quote) ⊆ normalize(选项[key])`（逐字取自选项）②`normalize(quote) ⊄ normalize(材料原文)`（**反向**：必须找不到）③归一化长度 ≥ 20 |

**类型 ↔ 陷阱强制对应（新增硬闸门，408 侧没有）**：

| 陷阱 id | 标签 | 允许的 kind | 校验失败时的处理 |
|---|---|---|---|
| `en-trap-swap` | 偷换概念 | `contrast` | 整条判废 |
| `en-trap-reverse` | 正反混淆 | `contrast` | 整条判废 |
| `en-trap-subject` | 张冠李戴 | `contrast` | 整条判废 |
| `en-trap-overreach` | 过度推断 | `contrast` | 整条判废 |
| `en-trap-partial` | 以偏概全 | `contrast` | 整条判废 |
| `en-trap-absent` | 无中生有 | **`absent`** | 整条判废（不允许改用 `contrast`） |
| `en-trap-irrelevant` | 答非所问 | **无允许值** | **强制降级为 probe**（只提问） |
| 完形：`en-trap-collocation` / `-sense` / `-logic` / `-tone` / `-grammar` | 搭配不当 / 词义不符 / 逻辑不通 / 褒贬色彩 / 语法不符 | `context` | 整条判废 |

**为什么「答非所问」必须走 probe**：这类干扰项的毛病不在原文——它在原文里**说得对**，只是没回答题干问的那件事。所以**不存在**能支撑「它错在哪」的原文句子。强行要求引用只会逼模型编造。让它走 probe 是唯一诚实的处理。

### 3.2 正向锚定：`locate` / `contrast` / `context`

三条都靠同一个已实现的函数 `verifyQuote(quote, source)`（`scripts/ai-guide/lib/grounding.mjs`，**无需改动**），只是 `source` 从「解析文本」换成「材料原文」。

新增的三条英语专有校验，都是很短的纯函数：

```
① 通道分离（防「把选项当原文」）
   英语的选项和原文都是英文，模型完全可能把选项文本当成"原文引用"交上来，
   而它在字符串层面看起来完全合理。校验方式：
     if (isSubstring(normalize(quote), normalize(option[key]))) → 判废
   理由：contrast 的引用就该是"被改写的原文句"，它不应是选项本身的子串。

② 空位覆盖（完形专用）
   先用「空白与空位标记均容忍」的方式在材料里**定位**该引用，取出匹配区间，
   断言该区间包含目标空位标记。做成两步而不是纯 substring：
     step1  quote 去掉 {{N}} 后，必须在「材料去掉所有 {{N}}」里找到（子串）
     step2  quote 里必须出现目标空位（正则 /\{\{\s*N\s*\}\}/）
   —— 两步合起来保证：引用既逐字来自原文，又确实指着这一空。

③ 反向断言（absent）
   断言「原文没有这句话」是可以被**伪证**的：只要那句话在原文里找得到，断言即假。
   所以这条规则在"它出错的方向"上是可机械验证的 —— 这正是它比普通结论更可靠的原因。
```

### 3.3 反向锚定为什么值得单独设计

`absent`（无中生有）是考研阅读**最高频**的干扰项类型之一，而它天然**没有**可正向引用的句子。直觉结论是「这类只能靠模型判断，所以不可靠」。但换一个方向看：

| | 正向锚定（locate/contrast/context） | 反向锚定（absent） |
|---|---|---|
| 模型断言 | 「原文里有这句话」 | 「原文里**没有**这句话」 |
| 可验证性 | 存在性可验证（找得到即真） | 不存在性**不可**全验证（找不到可能只是换了说法） |
| 但它出错的方向 | 编造句子 → 找不到了 → **判废** | 无中生有其实有出处 → **找得到** → **判废** |
| 结论 | 校验器能拦住模型的错 | **校验器同样能拦住模型的错** |

**关键**：断言"不存在"的**证伪**只需找到一处，这是可计算的。所以 `absent` 的校验方向是「必须找不到」——一旦找到就判废。加上 keyPhrase 必须逐字取自选项（防模型自己造一个关键词组），这条规则就同时锚定了**两端**：一端锚在选项（可信），一端锚在原文（可信）。

**残留弱点（诚实记录）**：模型仍可能挑一个"确实不在原文里、但也不代表选项主旨"的琐碎措辞来通过校验。对策是长度阈值 ≥ 20（实测：阅读干扰项归一化长度 p5 = 10、中位 32，20 的门槛放行 **83.7%** 的干扰项）+ **`absent` 条目 100% 进 `needsReview` 人工优先抽检**，不给它「已锚定」的功劳。

### 3.4 归一化必须补的两处映射（实测 100% 误判）

这是本文档**优先级最高的一条实现要求**。

现状：`normalizeForMatch()`（`grounding.mjs:99`）的 `PUNCT_MAP` 里**没有弯引号的映射**。实测后果：

| 实验（179 个含弯引号的句子） | 判废率 |
|---|---|
| 引用「原样抄」原文（保留 `“ ”`） | **0 / 179 = 0.0%** |
| 引用把弯引号「改直」成 `"`（模型最常见的输出形态） | **179 / 179 = 100.0%** |
| 在 `PUNCT_MAP` 补上 `“ ” → "` 之后，改直也能命中 | **179 / 179 = 100% 命中** |

也就是说：**不补这两行映射，含弯引号的 179 个句子所对应的所有诊断会被系统性全部判废**，而模型完全不知道自己做错了什么（它会以为自己引用得很准）。

**要求的改动**（对 408 无副作用，纯增召回）：

```js
// grounding.mjs · PUNCT_MAP 增补
'\u2018': "'", '\u2019': "'",   // ‘ ’ → '
'\u201c': '"', '\u201d': '"',   // “ ” → "
'\u2013': '-', '\u2014': '-',   // – — → -（与既有 '—': '-' 一致）
```

> 注意 `'\u2014'`（em-dash）在现有 `PUNCT_MAP` 里已经有 `'—': '-'`，因为那是**全角破折号 U+2014** 与 en/em dash 恰好同码位；`'\u2013'`（en-dash，94 处）是**真正缺失**的那个。
>
> 这条改动属于对既有模块的修改，**必须补一条回归断言**（含弯引号的正常引用不能被误判为不存在），并入 `test-grounding.mjs`。

### 3.5 阈值标定（全部来自实测，不是拍的）

**引用长度下限**：用「归一化后 N 字符的片段在材料内能命中几处」来衡量定位力（每篇随机抽样 40 次，70 篇共 **2,800 次**）：

| 归一化长度 N | 出现多处命中的比例 | 单片段最多命中处数 | 结论 |
|---:|---:|---:|---|
| 6（408 侧现值） | **15.5%** | 13 | 无定位力，不可用 |
| 12 | 2.4% | 7 | 偏弱 |
| 20 | 0.2% | 4 | 可用 |
| **25** | **0.1%** | **2** | **建议取值** |
| 30 | 0.0% | 2 | 更严 |
| 40 | 0.0% | 1 | 过严（部分真引用会更短） |

> 英文归一化会去掉所有空白，所以「25 字符」≈ 3.5 个单词。**英语侧 `minLen = 25`**（408 侧保持 6，不动）。

**完形片段长度上限**：空位所在句最长 **496** 字符、p75 = 185。上限设 **400 字符（原始长度，未归一化）**——允许跨句窗口，但挡掉「直接把整段贴上来」的偷懒引用（那等于没定位）。

**absent 的 keyPhrase 下限**：取 **20**（归一化）。依据来自上表 R1：阅读干扰项归一化长度 min/p5/p25/中位 = 6/10/26/32，阈值 20 时 **83.7%** 的干扰项可走 `absent`，只挡掉最短、最容易被"挑碎片"的那些。

### 3.6 英语的材料体检：只留结构性判据

**为什么不能照搬 408 的 A6 内容同源检测**——§0.2 已给出实测：完形选项与材料实词重合天然为 0；阅读正确项 28.6% 与原文零原词重合。套用会把大量正常题误判为错位。

英语的材料体检（`P1–P4`），**全部是结构性的、不涉及语义**：

| 判据 | 内容 | 实测结果 | 不通过时 |
|---|---|---|---|
| **P1 存在性** | 每个 `materialId` 能找到材料 | **0 悬空** | 该题走 probe，并进 `mat-warn` |
| **P2 完整性** | 材料末字符是句末标点（`.`/`?`/`!`/`”`/`”`）—— 判是否被抽取截断 | **0/70 截断** | 该篇全部题目走 probe |
| **P3 空位标记** | 完形材料的 `{{1}}`…`{{20}}` 各出现恰好一次 | **0/14 异常** | 同上 |
| **P4 挂载一致性** | 一篇材料的题目数（完形 20 / 阅读 5）与题号区间自洽 | **0 例外** | 同上 |

**没有任何一题不通过 P1–P4。** 这不意味着体检无用——它意味着**英语侧的健康度远高于 408**，也意味着 `mat-warn-en.json` 上线时应该是**一个空对象**。留着它是因为：题库以后会扩（2024–2025 待补录），而"结构性判据在扩容时最容易破"。

**关于「段落引用交叉校验」的实测结论（不做成闸门）**：题干含 `Paragraph N` / `Line N` 引用的阅读题只有 **74/280 = 26.4%**，覆盖率太低；且 `Line`（行）与「段落数」不是同一个量纲，**越界不等于错位**（实测越界 0 例，但这个 0 不能作为可信度证据）。→ 降级为**产物里的一条 warning 字段**，供人工抽检参考，**不参与判废**。

### 3.7 路径 G / P 在英语侧的触发条件

408 的分流是「解析可用 → G；否则 → P」。英语的分流判据换成材料体检：

```
材料通过 P1–P4  ──→ 路径 G（锚定模式）：
                      · 正确选项：必须给 locate 引用
                      · 干扰项：按 trap 决定 kind ∈ {contrast, context, absent}
                      · 每条都必须在材料里命中

材料未通过体检  ──→ 路径 P（提问模式）：
                      · 只出 probe，禁止任何结论性表述
                      · 复用 408 侧已有的 ASSERTION_MARKERS 黑名单

trap = en-trap-irrelevant（答非所问）
              ──→ 该条单独降级为 probe（即使材料通过体检）
```

**预期分流比例**：材料体检 70/70 通过，所以英语侧**几乎全部走路径 G**——这与 408 侧「11/40 题走路径 P」形成对比。这是 D1 选对了的直接体现：**换了一个干净语料，路径 P 就从"常态"变成了"异常兜底"。**

## 4 · 数据模型设计

### 4.1 设计原则（三条）

1. **原文不进产物**。`MATERIALS` 已在运行时内存里（`quizStore.ts:41`），产物只存**引用片段 + 定位信息**（`offset` / 段落号）。若把原文复制进指引产物，70 篇会多出 17.3 万字符的重复数据，且失去「原文改了、指引自动失配报警」的能力。
2. **派生物不污染数据源**（继承 408 的既有决定）：标注结果单独出 `tags-en.json`，**不回写** `english.json`。
3. **调度单位与分片单位一致 = 材料**。产物按篇切分，理由见 §5.3。

### 4.2 新增文件清单

| 文件 | 体积（预估） | 内容 |

```ts
    diagByMaterial: (q) => q.materialId ? `guide/diag/en/${q.materialId}.json` : null },
  { subject: '完形填空', /* 同上 */ },
]

// ② API 增加 loc
export interface GuideEntry {
  topic: string | null; mt: string | null; grounded: boolean
  src: 'explanation' | 'probe' | 'passage'
  loc?: { quote: string; kind: 'locate'; para?: number; offset?: number }
  d: Record<string, DiagItem>
}

// ③ DiagItem.evidence.kind 放宽为联合类型
evidence?: { quote: string; kind: 'conclusion'|'criterion'|'locate'|'contrast'|'context'|'absent' }
```

**加载器本体（Promise 缓存 + 静默降级 + `document.baseURI`）一行不改**——分片寻址的差异被 `diagByMaterial` 吸收掉了。这是 408 侧把 `RESOURCES` 做成表驱动的回报。

### 5.3 批处理粒度与请求数（为什么按材料调度）

| 方案 | 请求数 | 输入字符 | 问题 |
|---|---:|---:|---|
| 按题调度（每题各发一次原文） | 560 | 阅读 280 × (2,676+121+1,200) + 完形 280 × (1,682+121+1,200) ≈ **1,960,000** | 同一篇原文重复发 5–20 次；模型看不到同篇其他题，可能对同一句话给出矛盾诊断 |
| **按材料调度（本方案）** | **112** | **446,208** | 阅读 56 篇 ×1 次；完形 14 篇 ×4 次（20 题分 4 批，每批 5 题） |

**输入量降到约 1/4.4**，而更大的收益是**跨题一致性**：同一篇材料里的 5 道阅读题一起交给模型，它就不会把第 1 题的定位句又拿去解释第 3 题。

**每批为什么是 5 题而不是 20 题**（完形）：20 题 × (3 条诊断 + 引用) ≈ 20 × 220 token ≈ 4,400 token 输出，加上完形材料的定位复杂度（每空要判断语义场），一次请求的输出过长会显著抬高中途格式崩坏的概率。**5 题/批 ≈ 1,100 token 输出**，是可靠区间。

### 5.4 哈希与幂等

英语的幂等粒度是**两级**，这是 408 没有的：

```
材料级哈希 = hash(materialText, PROMPT_VERSION)
题目级哈希 = hash(stem, options, answer, 材料级哈希, mt, PROMPT_VERSION)
```

| 变化 | 失效范围 | 说明 |
|---|---|---|
| 材料正文改一个字 | **该篇的全部题（5 或 20）** | 所有引用都可能失配，必须整篇重跑 |
| 某题选项改一个字 | 该题 | — |
| 题型标注改一个 | 该题 | 骨架与陷阱库随之变化 |
| 提示词版本号 +1 | 全部 | 强制全量重跑 |

**材料级哈希是必需的**：如果只按题目哈希，材料被修正后题目哈希不变 → 引用已失配但不会重跑，产物会静默错误。这条是 408 侧 A6 那次教训的同构版本（「题库改了但产物没重跑，verify 会红，但 build 不会自动修」）。

### 5.5 质量闸门

写盘前必须全部通过，任一不过则该条**整条丢弃**（继承 408 的「宁缺勿错」）：

| # | 闸门 | 判废条件 |
|---|---|---|
| 1 | 引用归属 | 引用在材料里找不到（含 §3.4 归一化后） |
| 2 | **通道分离** | 引用是某选项的子串（模型把选项当原文引用）→ **英语专有，最高优先级** |
| 3 | 空位覆盖（完形） | 引用不含目标 `{{N}}`；或引用原始长度 > 400 |
| 4 | 长度阈值 | `locate`/`contrast` < 25（归一化）；`absent` < 20 |
| 5 | 类型绑定 | `trap` 与 `evidence.kind` 不匹配（§3.1 表） |
| 6 | 反向校验（absent） | keyPhrase 在材料里**找得到**（断言被伪证）；或 keyPhrase 不是选项的子串 |
| 7 | 正确项不得被诊断 | 诊断只能落在非正确项（继承 408） |
| 8 | 空话 / 复述答案黑名单 | 继承 408（注意：`ANSWER_RESTATE_PATTERNS` 是中文黑名单，英语需补英文等价物，如 `\bthe answer is\b`、`\bchoose [A-D]\b`） |
| 9 | 长度上限 | 诊断 ≤ 80 字（中文表述），继承 408 |

## 6 · 运行时集成设计

### 6.1 挂载点：复用现有面板，加两个区块

英语一**不需要新的挂载点**。`QuestionCard.tsx` 里 `<AiGuide question={question} revealed={grade.answered} />` 一行不用改，`AiGuide.tsx` 内部按 `hasGuide(subject)` 自动生效。改动集中在面板内部：

| 区块 | 408 现状 | 英语一 | 显示时机 |
|---|---|---|---|
| 知识点 | ✅ | ✅ 复用（`en-r-3 回文定位`） | 作答前 |
| 前置知识 | ✅ | ✅ 复用（`题型识别 → 关键词提取 → 回文定位`） | 折叠 |
| 母题 | ✅ 折叠 | ✅ 复用（题型 + 解题骨架 + 陷阱库） | 作答前折叠 |
| **定位句**（新增） | — | **正确选项对应原文哪一句** + 段落号 | **仅作答后** |
| 干扰项诊断 | ✅ | ✅ 复用，徽标文案换四档 | **仅作答后** |
| **本空所在句**（新增，完形专用） | — | 空位所在句原文，**高亮该空位** | 作答前（它就是题干） |

**徽标文案（英语四档，与 `evidence.kind` 一一对应）**：

| kind | 徽标 | 含义 |
|---|---|---|
| `locate` | **定位原文** | 这句话就是答案的出处 |
| `contrast` | **原文改写** | 原文说的是这句，选项把它改了 |
| `context` | **本空语境** | 这一空的判断依据就在这段里 |
| `absent` | **原文无此说** | 这个说法在原文里找不到落点 |
| （probe） | **请你自己定位** | 该条未获可信锚定，只给引导 |

**完形的「本空所在句」为什么必须做**：题目自带的题干只是「第 3 空」，而长文在题卡上方是**折叠**的（`MaterialPassage` 的 `<details>`），学生要来回展开、在 1,700 字符里找第 3 空。把「含该空的句子」单独提出来并高亮，是英语一片材料挂 20 题带来的**必须有的可用性补偿**。

### 6.2 加载策略与体积

| 项 | 策略 |
|---|---|
| 寻址 | 按 `materialId` 取片：`guide/diag/en/en-2020-read1-passage.json` |
| 缓存 | 缓存 **Promise**（不是结果）—— 同一片在并发首屏只发一次请求（继承 `guide.ts` 现有实现） |
| HTTP 缓存 | `fetch(url, {cache:'force-cache'})` |
| 首屏影响 | **零**——产物在 `public/`，不进 bundle；`data-english-*.js` 的 346.75 kB 保持不变 |
| 单会话典型下载量 | 阅读 1 片 ≈ 5 KB；完形 1 片 ≈ 15 KB |
| 最坏情况 | 一次筛选命中全部 14 篇完形 → 14 片 ≈ 210 KB（且仅首轮，之后走缓存） |

### 6.3 降级设计（必须做，且逐层独立）

| 失败点 | 表现 | 降级行为 |
|---|---|---|
| 分片 404 / 网络失败 / JSON 损坏 | 题级诊断不可用 | 静默 `null`，**面板整体不渲染**，作答流程不受影响 |
| `materialId` 缺失 | 无法寻址分片 | 只渲染题型层（知识点 / 前置知识 / 母题），不渲染题级内容 |
| `loc` 缺失 | 无定位句 | 只渲染干扰项诊断 |
| 母题库缺失但知识点图在 | 骨架/陷阱不可用 | 只渲染知识点与前置知识 |
| 知识点图缺失 | 图节点查不到 | 只渲染母题与题级内容 |
| 全部缺失 | — | `return null`（与 408 一致） |

**硬规则（继承 408）**：指引是增强项，**任何失败都不得抛出、不得阻塞作答、不得让页面白屏**。

### 7.3 结论：成本约束比 408 侧还弱，人力依旧是唯一约束

| 成本项 | 量级 |
|---|---|
| **API 费用（英语一全科 560 题）** | **不到 ¥10**（旗舰档），常用档 **不到 ¥1** |
| 对比：数据结构的显式约束 | 408 全库四科约 ¥1 ~ ¥30 |
| **人工审核（M1 · 2020 一整年 40 题）** | **约 1 小时**（160 条：120 条干扰项诊断 + 40 条定位句） |
| **人工审核（英语一全科 560 题）** | **约 8 ~ 12 小时**（1,680 条诊断 + 560 条定位句，按 408 侧实测的审核速度外推） |
| 新增的隐性成本（英语独有） | **题型标注与母题骨架的建立**：28 节点图 + 20 母题 + 12 陷阱库 + 标注规则，人工约 **6 ~ 10 小时**（一次性，可跨科目复用思路但内容不可复用） |

**所以本方案的重心与 408 一致：把力气花在降低审核成本上。** 三条具体手段：
1. **待审条目按置信度排序**：`absent`（反向锚定，最弱）> `contrast` > `context` > `locate`（最强），审核时从弱到强；
2. **按材料组织审核**：一次只看一篇的 5（或 20）条，比跨篇跳着看快得多——这也是分片按材料切的第二个理由；
3. **诊断写短**（≤80 字）+ 引用可当场核对（原文就在屏幕上方），单条判定时间压到 10 秒内。

## 8 · 风险与对策

| # | 风险 | 严重度 | 对策 |
|---|---|---|---|
| **E1** | **模型「背题」**：模型见过 2010–2023 真题，可能凭记忆写出与原文无关但"看起来对"的诊断——而逐字校验只约束**引用**，不约束**结论** | **高** | 引用必须命中材料（拦住编造引用）；`absent` 走反向校验；**但引用真 ≠ 结论真**，这条只能靠人工抽检——所以 `contrast` 类也必须抽样，不能默认信任。这是本方案**唯一无法自动化**的风险 |
| **E2** | **通道混淆**：英语的选项与原文同为英文，模型可能把**选项文本**当"原文引用"交上来，字符串层面完全合理 | **高** | §5.5 闸门 2「通道分离」：引用若是某选项的子串即判废。**英语专有，408 没有对应风险（中文解析 vs 中文选项也存在，但当时未做此校验）** |
| **E3** | **弯引号导致正确引用被系统性判废** | **高** | §3.4：补 `PUNCT_MAP` 映射（实测 179/179 → 全数命中）+ 回归断言 |
| **E4** | **引用命中但命中的是错位置**（英文重复短语多于中文） | 中 | `minLen = 25`（实测 0.1% 多处命中）；产物存 `offset`，同一引用多处命中时判废 |
| **E5** | **完形空位标记被改写** | 中 | 提示词铁律「必须原样保留 `{{N}}`」+ 双侧剥离比对 + `{{N}}` 存在性检查（实测：`{{ 1 }}` 可通过，`[1]`/`___` 不通过） |
| **E6** | **`absent` 被滥用**为「我找不到就说过无」 | 中 | keyPhrase 必须逐字取自选项 + 归一化长度 ≥ 20 + **全部进 `needsReview`**，不记入「已锚定」 |
| **E7** | **答非所问类干扰项无从锚定** | 中 | 强制走 probe，不出结论（§3.1） |
| **E8** | **定位句作答前泄露** | 中 | `loc` 与干扰项诊断共用 `revealed` 门（`grade.answered`）；`smoke-cdp.mjs` 新增断言「作答前 `loc` 数量必须为 0」 |
| **E9** | **分片数上升（70 片）** | 低 | 按需加载 + Promise 缓存 + `force-cache`；最坏 14 片 ≈ 210 KB |
| **E10** | **题型标注歧义**（细节题 vs 推断题边界模糊） | 中 | 规则 + `overrides`，歧义不猜（继承 408 的 `ambiguous` 机制）；M1 实测歧义率后再定粒度（§10 · Q4） |
| **E11** | **母题骨架对英语是否有用未知** | 中 | 英语的"骨架"是解题步骤（定位→比对→排除），比 408 的算法推演更偏方法论；M1 后必须回看学生是否真的用得上（§9） |
| **E12** | **考纲/题型调整导致内容过时** | 低 | 产物带 `version` + `promptVersion`；状态文件支持按材料 id 定向重跑 |

**E1、E2、E3 是仅有的三条"会造成实际伤害"的风险**：E1 让学生学到错的思路，E2 让机制形同虚设（引用全是真的，只是真的不是原文），E3 让产出静默归零。三条都在设计上留了闸门或强制人工环节。

## 9 · 分阶段实施计划

**原则（继承 408）：先打样一科一段，验证机制与审核成本，再决定是否铺开。**

### M1 · 2020 一整年打样（验证机制）

选 2020 一整年，不是随机抽样——理由是**一整年在练习页里是可用的最小闭环**（学生可以按年份筛选做完整一套），而 5 篇材料同时覆盖两种题型与完形/阅读两种语境形态。

| 步骤 | 交付 | 验收标准 |
|---|---|---|
| 1.1 材料体检 | `lib/passage-audit.mjs` | P1–P4 全部可跑；`mat-warn-en.json` = `{}`（实测预期 0 异常） |
| 1.2 补归一化映射 | `grounding.mjs` 改动 | 含弯引号的引用全部命中；`test-grounding.mjs` 新增断言后仍全绿（103 → ≥108 项） |
| 1.3 建知识点图 | `kg-en.json` | 28 节点；拓扑无环；每节点 `summary` 非空；边全部人工确认 |
| 1.4 编母题与陷阱库 | `mothers-en.json` | 20 母题；每个 ≥3 步骨架且都有陷阱库；12 个陷阱 id 全局唯一 |
| 1.5 题型标注 | `tags-en.json`（2020 部分） | 2020 的 40 题覆盖 ≥95%；歧义条目转人工不猜 |
| 1.6 生成诊断（8 次请求） | `diag/en/en-2020-*.json`（5 片） | 全部通过 §5.5 九道闸门；预计 ~120 条干扰项诊断 + 40 条定位句 |
| 1.7 英语校验器 | `lib/grounding-en.mjs` + `test-grounding-en.mjs` | ≥90 项断言；含**故意写坏**的样本（把选项当原文引用 / 弯引号改直 / 空位标记丢失 / absent 被伪证 / 类型绑错），全部必须被判废 |
| 1.8 前端接入 | `AiGuide.tsx` + `guide.ts` | 渲染冒烟通过；作答前 `loc` 与干扰项诊断数量均为 0 |
| 1.9 真实渲染抽检 | `docs/shots/` 3 张图 | 阅读题（定位句 + 4 档徽标）/ 完形题（本空所在句高亮）/ 降级（断网不炸） |

**M1 完成后必须回看三个问题再决定是否继续**（与 408 侧同一套门槛）：
1. **抽检准确率**是否达标（§10 · Q5 定验收线；408 侧定的是 90%）；
2. **审核耗时**是否与预估的「40 题 ≈ 1 小时」相符；
3. **题型骨架对学生是否真有帮助**——如果学生只看定位句、从不点开母题骨架，那 M2 就该砍掉骨架的投入，把力气全部放在定位句与干扰项诊断上。

### M2 · 其余 13 年铺开（纯执行）

2010–2019 + 2021–2023，共 520 题 / 65 篇材料。**这一步不应再出现新的设计问题**——若出现，说明 M1 的抽象不够。届时应已能确认：分片粒度、批大小、提示词是否稳定。

### M3 · 增量维护（接近零成本）

题库以后补录 2024–2025 英语（预计 80 题 / 10 篇材料）：材料级 + 题目级哈希只处理新增部分，API 成本 < ¥1、人工 < 40 分钟。

### 验证脚本

**第一层：`scripts/verify-guide-en.mts` —— 产物契约（7 组）**

```
[E1 分片与 schema]   70 片（M1 为 5 片）；每片 materialId 自述与路径一致
                     占位符：M1 后应为 5 片，逐片 stats 与重算值一致
[E2 引用重校验]      ★ 每条 quote（locate/contrast/context）拿回 english.json 的
                       当前材料重新逐字匹配 —— 不信任构建期日志
[E3 反向校验]        每条 absent：quote ⊆ 选项 且 quote ⊄ 材料（双向，缺一不可）
[E4 空位覆盖]        每条 context 的 quote 确实覆盖其 {{N}}；原始长度 ≤ 400
[E5 类型绑定]        trap ↔ evidence.kind 完全符合 §3.1 表；无例外
[E6 通道分离]        没有一条 quote 是某个选项的子串
[E7 覆盖率与体积]     题型标注覆盖率 ≥95%；单阅读片 ≤ 20KB / 单完形片 ≤ 40KB；
                     诊断无一条落在正确选项上
```

**E2 + E3 是这一层的核心**：E2 是「正向锚定必须仍然成立」，E3 是「反向锚定必须仍然成立」——它们都**不信任构建期状态**，而是把产物拿回当前题库重新算一遍。题库改一个字而产物没重跑，这里立刻红。

**第二层：`scripts/smoke-cdp.mjs`（新增 M / N 两节）**

```
[M · 英语指引面板]
  选中英语一 + 阅读理解 → 作答前：loc 区块数量 = 0 ★
                         作答前：干扰项诊断数量 = 0 ★
                         作答前：母题骨架折叠、不渲染步骤
                         作答后：出现定位句，含段落号
                         作答后：每条诊断带四档徽标之一，且与 kind 一一对应
                         `原文无此说` 徽标不得给出「原文」展开按钮（没有原文可展开）
[N · 完形指引面板]
  选中英语一 + 完形填空 → 作答前：渲染「本空所在句」，且高亮该空位 ★
                         作答后：诊断徽标为「本空语境」或「请你自己定位」二选一
  两节均断言 Runtime.exceptionThrown 为空（防白屏）★
```

**尚未纳入自动化的一项**（与 408 相同）：「同一材料连续多题只发起 1 次分片请求」。靠代码形态保证（缓存 Promise 而非结果），要实测需开 CDP Network 域统计，收益不高，暂留人工。
