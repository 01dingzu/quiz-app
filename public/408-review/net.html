考点 1 · 体系结构与数据链路层

时延计算、滑动窗口、CRC、CSMA/CD

时延四件套：发送时延 = 帧长/带宽（与距离无关）；传播时延 = 距离/速率；处理+排队时延在节点内。发送时延和传播时延谁占主导看场景，别默认谁大。

滑动窗口边界（n 位序号）：停等 W=1；GBN 发送窗口 ≤ 2ⁿ − 1（接收窗口 1）；SR 发送窗口 ≤ 2ⁿ⁻¹（发送+接收窗口 ≤ 2ⁿ）。超界会新旧帧序号混淆。

CRC：数据后补 k 个 0（k = 生成多项式最高次数）对生成多项式做模 2 除，余数即 FCS，附在数据后发送。

CSMA/CD：争用期 = 2τ（两倍端到端传播时延）；最小帧长 = 2τ × 数据率——保证发完前能检测到最远的冲突。以太网用截断二进制指数退避。

设备：集线器（物理层）不隔离冲突域；交换机（链路层）隔离冲突域、自学习建转发表；路由器（网络层）隔离广播域。

例题 · CRC 计算推演
数据 M = 101001，生成多项式 P = 1101（x³+x²+1）。求 CRC 校验序列与实际发送的帧。
展开完整推演 
多项式最高次为 3 → 补 3 个 0:
  被除数 = 101001000，模 2 除以 1101:

  1010 ⊕ 1101 = 0111   ↓0 → 1110
  1110 ⊕ 1101 = 0011   ↓1 → 0111
  (前导 0 跳过) 1110 ⊕ 1101 = 0011
  ↓0 → 0110 ⊕ 1101 … 110 ⊕ 0 → 1100
  1100 ⊕ 1101 = 0001 → 余数 = 001

FCS = 001
发送帧 = 101001 001（共 9 位）

验算法：把 101001001 再除以 1101，余数应为 000。模 2 除法全程 XOR 不借位，余数位数 = 补 0 个数。

考点 2 · IP 地址与子网划分

必考计算：划分子网、聚合、最长前缀匹配

子网划分：借主机位做子网位。/26 = 借 2 位 → 4 个子网，每子网主机位 6 → 可用主机 2⁶ − 2 = 62（去掉全 0 网络地址和全 1 广播地址）。

判断归属：地址 AND 掩码 == 子网网络地址，即属于该子网。

CIDR 聚合：前缀相同的连续网络可向上聚合（掩码变短）；聚合的块必须能被"2^(扩展位数)"整除对齐。

最长前缀匹配：多个路由表项都匹配时，选前缀最长（最具体）的那个。

配套协议：ARP（IP→MAC）、DHCP（自动配置，Discover/Offer/Request/Ack）、ICMP（差错与询问）、NAT（私网地址转换）。

例题 · 子网划分与归属判断
把 192.168.1.0/24 等分为 4 个子网。① 每个子网的掩码与可用主机数？② 主机 192.168.1.100 属于哪个子网？
展开完整推演 
① 4 = 2² → 借 2 位 → /26
   掩码 = 255.255.255.192
   每子网主机位 6 位 → 可用 2⁶−2 = 62 台
   子网: 192.168.1.0/26, .64/26,
        .128/26, .192/26

② 100 落在 64~127 之间
   （100 = 01100100，第 3、4 位 = 01 → 第二个子网）
   ⇒ 属于 192.168.1.64/26

快速法：看借来的位。100 的二进制 01100100，高两位 01 = 子网编号 1，即从 64 开始的子网。

考点 3 · 路由协议

RIP / OSPF / BGP 三兄弟对照表

RIP：距离向量算法，以跳数为度量（≤16，16=不可达）；与相邻路由器周期性交换整个路由表；用 UDP（520 端口）封装；毛病："坏消息传播慢"（收敛慢，计数到无穷）。

OSPF：链路状态算法，向全网泛洪链路状态通告，各节点自己跑 Dijkstra；直接用 IP（协议号 89）封装；支持划分区域、收敛快。

BGP：外部网关协议（AS 之间），路径向量，求"可达且较合理"而非最优；用 TCP（179 端口）。

记忆锚：RIP-UDP-内部、OSPF-IP-内部、BGP-TCP-外部。

例题 · RIP 路由更新推演
路由器 X 的路由表中"到 B 的距离 = 5，下一跳为 R"。邻居路由器 C 发来通告："到 B 的距离 = 2"。X 与 C 直接相连（距离 1）。X 的路由表如何更新？
展开完整推演 
RIP 更新规则：
新候选距离 = 1 (X到C) + 2 (C到B) = 3
比较: 3 < 原距离 5
⇒ 更新为：到 B 距离 3，下一跳改为 C

若新候选距离 ≥ 原距离 且 下一跳不是 C：
  不更新（保留原路由）

两个坑：① 候选距离要加上"到通告者的距离"，不是直接比较 2 和 5；② 若下一跳本来就是 C，即使新距离更大也要照抄——因为走的就是这条路。

考点 4 · TCP

大题双铁王座之一：握手挥手 + 拥塞控制窗口推演

序号与确认：TCP 面向字节流，序号 = 本段第一个字节的编号；确认号 = 期望收到的下一个字节序号（累积确认）。SYN、FIN 各占一个序号。

三次握手：第三次（客户端 ACK）防止"已失效的连接请求"再次到达服务器造成资源浪费。四次挥手：主动方最后进入 TIME_WAIT 等 2MSL——保证最后的 ACK 若丢失可重发 + 让旧报文在网络中消逝。

流量控制：接收窗口 rwnd，滑动窗口，防止淹没接收方。

拥塞控制四招：慢开始（cwnd 从 1 指数涨到 ssthresh）→ 拥塞避免（线性 +1）→ 超时：ssthresh = cwnd/2，cwnd 回到 1 重新慢开始；快重传（3 个重复 ACK 立即重传）+ 快恢复：ssthresh = cwnd/2，cwnd = 新 ssthresh（不回到 1）。

例题 · 拥塞窗口全程推演
cwnd 初始为 1，ssthresh = 8（单位：报文段）。从慢开始到 cwnd=12 时发生超时。写出整个拥塞窗口变化过程。
展开完整推演 
阶段一（每 RTT）:
1, 2, 4, 8   ← 慢开始，指数增长到 ssthresh
9, 10, 11, 12 ← 拥塞避免，线性 +1

cwnd=12 时超时:
  ssthresh = 12/2 = 6
  cwnd = 1，重新慢开始
1, 2, 4, 6  ← 4 的下一轮按指数应为 8，
              超过 ssthresh=6，故封顶取 6
7, 8, ...   ← 转入拥塞避免线性增长

判分要点：① 慢开始与拥塞避免的分界是 ssthresh；② 超时回 1、快恢复不回 1；③ 指数增长越过 ssthresh 时要"封顶"。

考点 5 · 应用层

协议-端口-传输层绑定关系是选择题套餐

DNS：域名 → IP；查询用 UDP 53（区域传送用 TCP）；递归查询（主机→本地服务器）+ 迭代查询（本地服务器→根/顶级/权限）。

FTP：控制连接 21（全程保持）+ 数据连接 20（按需建立）；控制是带外传送。

电子邮件：发信 SMTP（推）；收信 POP3/IMAP（拉）；邮件网关之间也用 SMTP。

DHCP：UDP，Discover → Offer → Request → Ack 四步，即插即用获取 IP/掩码/网关/DNS。

HTTP：无状态，Cookie 弥补；非持久连接每对象 2×RTT（握手 + 请求响应），HTTP/1.1 默认持久连接；万维网文档用 URL 定位。

例题 · 非持久 vs 持久连接耗时
页面 = 1 个 HTML + 3 个图片引用，对象都很小（传输时间忽略），往返时延 RTT = 1s。分别求：① 非持久连接串行获取的总时间；② 持久连接（非流水线）的总时间。
展开完整推演 
① 非持久连接: 每个对象都要
   TCP 握手 1 RTT + 请求响应 1 RTT = 2 RTT
   4 个对象 × 2 RTT = 8 RTT = 8s

② 持久连接: 一次握手 1 RTT
   之后每个对象仅 1 RTT（请求+响应）
   = 1 + 4 = 5 RTT = 5s

要点：非持久的开销在"每个对象重复握手"；若允许并行连接，总时间还会更短——题目说"串行"就要串行算。

综合大题（TCP 序号与确认）

限时 12 分钟 · 序号确认号推演是网络大题的基本功
题目：主机 A 通过 TCP 向 B 发送三个连续报文段（均无数据丢失时）：第一段序号 100、携带 100 字节；第二段序号 200、携带 180 字节；第三段序号 380、携带 60 字节。① B 正确收到第一段、第二段后分别回送的确认号是多少？② 若第二段在中途丢失，第一段、第三段已到达 B，B 收到第三段时回送的确认号是多少？为什么？
展开参考答案与推演 
① 第一段: 占 100~199
   确认号 = 100 + 100 = 200（期望下一个字节）
   第二段: 占 200~379
   确认号 = 200 + 180 = 380

② 第二段丢失，B 只收到 100~199 和 380~439:
   确认号仍是 200（累积确认只认连续部分）
   并且 B 会重复发送确认号 200 ——
   A 连续收到 3 个重复 ACK(200)，
   触发快重传，不等超时立即重发第二段

评分点自查：① 确认号 = 已收到的最高连续字节 + 1；② 乱序到达时确认号不前移（累积确认）；③ 重复 ACK 与快重传的联动。把这三点写全，大题不丢分。
